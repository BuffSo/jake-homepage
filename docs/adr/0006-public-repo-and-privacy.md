# ADR-0006: 처음부터 공개 저장소로 운영하고 민감정보는 네 겹으로 막는다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

이 저장소의 목적 중 하나는 만드는 과정을 공개하는 것입니다([00-vision.md](../00-vision.md)). 하지만 공개 저장소의 git 이력은 나중에 지워도 사본이 남을 수 있습니다. 공개 푸시를 몇 분 안에 수집하는 봇도 있어서, 실수 한 번이 되돌릴 수 없는 노출이 됩니다.

## 검토한 안

AI는 비공개 저장소로 시작해 이력 전체를 점검한 뒤 공개로 전환하자고 제안했습니다. 공개 전에 실수를 발견하면 이력을 고쳐 쓸 수 있다는 이유였습니다.

## 판단

비공개로 작업해도 공개로 바꾸는 순간 그동안의 이력이 모두 공개됩니다. 보는 사람에게는 처음부터 공개한 것과 차이가 없습니다. 이력을 고쳐 쓰면 오히려 보여 주려던 실제 과정이 다듬어진 기록이 됩니다. 그래서 공개 전의 안전 기간에 기대지 않고, 커밋 전에 막는 데 집중하기로 했습니다.

## 결정

### 공개 방식

- 처음부터 공개 저장소로 만듭니다.
- 공개 저장소에 올라간 값은 지워도 회수할 수 없다고 봅니다. 키가 올라가면 즉시 폐기합니다.
- 커밋 이메일은 이 저장소에서만 GitHub noreply 주소를 씁니다.
- 대화 원문은 커밋하지 않습니다. devlog에는 요약만 씁니다.

### 막는 대상

전화번호, 주민등록번호 형식, 로컬 절대 경로, API 키와 토큰, 개인 키, 공개 연락처가 아닌 이메일, 그리고 비공개 금지어 목록에 있는 단어입니다.

비공개 금지어 목록은 `.sensitive-terms.local`(git 제외)에 둡니다. 목록 자체가 민감정보이기 때문입니다.

### 네 겹의 검사

| 겹 | 언제 | 무엇으로 |
|---|---|---|
| 1. git 훅 | 사람이든 에이전트든 커밋할 때 | `.githooks/pre-commit` → `scripts/check-sensitive.mjs --staged`. `.githooks/commit-msg`는 AI 서명이 든 커밋 메시지를 막습니다 |
| 2. Claude Code 훅 | 에이전트가 `git commit`을 실행하기 직전 | `.claude/settings.json` → `scripts/hooks/guard-git-commit.mjs`. `--no-verify`로 훅을 건너뛰는 것도 막습니다 |
| 3. GitHub 푸시 보호 | 푸시할 때 | secret scanning과 push protection이 키 형식의 값이 든 푸시를 거부합니다 |
| 4. CI | 푸시와 PR마다 | `.github/workflows/ci.yml`에서 저장소 전체 검사, gitleaks로 커밋 이력의 비밀값 검사 |

검사에 걸리면 값을 지웁니다. 규칙을 끄거나 예외를 늘려서 통과시키지 않습니다.

### AI 사용 표시

커밋 메시지에 AI 공동 작성자 줄을 넣지 않습니다. 커밋은 제가 내용을 확인하고 승인한 뒤에만 합니다. AI 활용은 이 문서들과 devlog, `CLAUDE.md`, 훅과 스크립트로 보여 줍니다.

## 영향

- 검사는 형식 기반이라 문맥상의 노출(예: 특정 회사 이름)까지 다 잡지는 못합니다. 그래서 커밋마다 사람이 diff를 확인합니다.
- 가장 위험한 순간은 이력서 md를 처음 가져오는 콘텐츠 동기화(F5)입니다. 이 커밋은 diff를 따로 검토하고, 전화번호가 빠졌는지 별도로 확인합니다.
- `npm install`을 하면 `prepare` 스크립트가 `core.hooksPath`를 `.githooks`로 설정합니다.
