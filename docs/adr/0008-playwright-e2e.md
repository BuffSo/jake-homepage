# ADR-0008: 화면 확인은 Playwright E2E로 자동화한다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

홈에는 눌러 봐야 확인되는 동작이 있습니다. 기술 층을 누르면 서비스가 강조되고, 다시 보기를 누르면 움직임이 다시 나오며, 움직임 줄이기 설정에서는 처음부터 마지막 장면이어야 합니다. 375px 화면에서 가로 스크롤이 없어야 하고, 콘솔 오류도 없어야 합니다.

지금까지의 검증 명령(lint, 타입, 테스트, 빌드, 민감정보 검사)은 이런 것을 보지 못합니다. 에이전트가 브라우저를 직접 조작해 확인할 수도 있지만, 남는 테스트가 없어 다음에 다시 할 수 없습니다. 같은 브라우저를 여러 에이전트 세션이 함께 쓰면 서로의 탭을 건드릴 수도 있습니다.

## 검토한 안

| 안 | 장점 | 단점 |
|---|---|---|
| Playwright (`@playwright/test`) | 세션마다 따로 띄운 헤드리스 브라우저. 움직임 줄이기와 다크 모드를 흉내 낼 수 있고, 콘솔 오류와 캡처를 바로 얻음. CI에서 돔 | 개발 의존성과 브라우저 설치가 늘고 CI 시간이 길어짐 |
| 에이전트가 브라우저를 직접 조작 | 의존성 없음 | 테스트가 남지 않음. 같은 브라우저를 쓰는 다른 세션과 간섭 |
| Puppeteer | 가벼움 | 테스트 러너와 단언을 따로 갖춰야 함 |

## 판단

다른 프로젝트처럼 구현 뒤 실제 화면을 조작해 확인하는 단계가 없다는 지적에서 시작했습니다. AI는 처음에 에이전트가 브라우저로 직접 확인하는 방식을 생각했지만, 여러 세션이 같은 브라우저를 쓰는 문제가 있었습니다. 그래서 자동 확인은 따로 띄운 헤드리스 브라우저로 하고, 사람에게 결과를 보여 줄 때만 브라우저의 새 탭을 쓰기로 했습니다.

## 결정

- `@playwright/test`를 개발 의존성으로 두고 Chromium만 씁니다.
- 테스트는 `e2e/`에 두고, `playwright.config.ts`는 `next build` 뒤 `next start`를 띄워 그 화면을 검사합니다.
- 화면 너비 375px와 1280px, 라이트와 다크, 움직임 줄이기 켬과 끔을 확인합니다. 콘솔 오류는 0건이어야 합니다.
- 캡처는 테스트 결과물로만 남기고 커밋하지 않습니다(`test-results/`, `playwright-report/`는 git 제외).
- `npm run test:e2e`로 돌리고, CI에서도 돌립니다.

## 영향

- 화면이 바뀌는 커밋에는 해당 동작의 E2E를 함께 넣습니다.
- F6(`npm run verify`)은 이 테스트를 포함합니다.
