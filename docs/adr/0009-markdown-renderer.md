# ADR-0009: 포트폴리오와 이력서 원문은 react-markdown으로 그린다

- 상태: 채택 (2026-10-16 CJK 강조 플러그인 추가)
- 날짜: 2026-10-15

## 배경

`/work`(F2)는 동기화한 포트폴리오(`content/synced/portfolio.md`)의 "4-1"~"4-3"과 "2", "3"의 일부를 문장을 다시 쓰지 않고 그대로 보여 줍니다([ADR-0003](0003-content-source-and-sync.md)). F4 `/resume`도 이력서 원문 전체를 같은 방식으로 그릴 예정입니다.

원문에는 표(GFM), 코드 블록, 인용, 원문 HTML(`<br>`, `<span style>`, `<img>`, `<sub>`)이 섞여 있습니다. 지금 의존성(next, react, yaml)에는 마크다운을 HTML로 바꾸는 것이 없어서 하나가 필요합니다.

그릴 때 해야 할 일은 이렇습니다.

- 외부 링크는 이미 있는 `ExternalLink` 컴포넌트(새 창, 스크린 리더 안내)로 엽니다.
- 원문 HTML의 `style` 속성은 버리고 사이트 클래스로 바꿉니다.
- 표는 모바일에서 가로로 넘길 수 있게 감쌉니다.
- 제목 단계를 페이지 구조에 맞춰 내립니다.

## 검토한 안

| 안 | 장점 | 단점 |
|---|---|---|
| `react-markdown` 10 + `remark-gfm` 4 + `rehype-raw` 7 | 요소마다 React 컴포넌트를 꽂을 수 있음(`a` → `ExternalLink`). 원문 HTML도 같은 트리로 읽어 `style`을 요소 단위로 버림. innerHTML을 쓰지 않음 | 설치되는 패키지 82개(약 6.2MB). react-markdown의 마지막 릴리스가 2025-03 |
| `marked` 18 | 패키지 1개(약 0.5MB), 의존성 0개, 꾸준히 릴리스됨 | 결과가 HTML 문자열이라 `dangerouslySetInnerHTML`로 넣어야 함. 원문 HTML은 문자열 그대로 지나가서 `style`을 지우려면 정규식으로 고쳐야 함. `ExternalLink`를 쓰지 못하고 같은 마크업을 문자열로 한 벌 더 둬야 함 |
| unified 직접 조립(`remark-parse`, `remark-rehype`, `hast-util-to-jsx-runtime` 등) | react-markdown과 같은 일을 하면서 단계를 직접 고름 | 패키지 110개로 오히려 많고, 조립 코드를 직접 관리해야 함 |
| 직접 만든 변환기 | 의존성 없음 | 표, 중첩 목록, 원문 HTML을 제대로 다루려면 결국 파서를 하나 만들게 됨 |

패키지 수와 크기는 빈 폴더에 각 안을 설치하고 `npm ls --all`로 셌습니다(2026-10-15). 세 안 모두 서버 컴포넌트에서 빌드 때만 돌기 때문에 방문자에게 내려가는 JS는 늘지 않습니다.

## 판단

- 의존성 수만 보면 `marked`가 낫습니다. [ADR-0007](0007-yaml-frontmatter.md)에서 `yaml`을 고른 이유와 같은 기준입니다.
- 그래도 F2, F3, F4 세 페이지가 같은 변환기를 쓰고, 링크와 원문 HTML을 사이트 컴포넌트로 바꾸는 일이 페이지마다 반복됩니다. 원문 HTML을 문자열 정규식으로 고치는 방식은 원문이 바뀌면 조용히 틀리기 쉽습니다.
- 늘어나는 패키지 82개는 빌드 때만 쓰입니다. 방문자 쪽 비용은 없고, 늘어나는 것은 설치 시간과 의존성 관리입니다.

## 결정

- `react-markdown` 10.1, `remark-gfm` 4.0, `rehype-raw` 7.0을 `dependencies`에 넣습니다.
- 서버 컴포넌트에서만 씁니다. `"use client"` 파일에서는 가져오지 않습니다.
- 요소를 사이트 컴포넌트로 바꾸는 규칙은 컴포넌트 한 곳에 모읍니다. 외부 링크, 표 감싸기, `style` 버리기, 제목 단계 조정이 여기에 들어갑니다.
- `rehype-sanitize`는 넣지 않습니다. 이 변환기로 그리는 글은 동기화 허용 목록과 민감정보 검사([ADR-0006](0006-public-repo-and-privacy.md))를 거친 원문과 사이트 전용 글뿐입니다. 방문자가 입력한 글은 이 변환기로 그리지 않습니다.
- 2026-10-16 추가: `remark-cjk-friendly` 2.3을 `remark-gfm` 바로 다음에 둡니다.
  - CommonMark는 닫는 `**` 바로 앞이 문장부호이고 바로 뒤가 글자이면 강조를 닫지 않습니다.
  - 한국어는 조사가 바로 붙어서 이 규칙에 자주 걸립니다. 예: `**\`DEMO Login\`**에서`
  - 이 플러그인은 한국어·중국어·일본어 글자 옆에서만 규칙을 넓히고, 이미 맞게 닫히던 강조는 바꾸지 않습니다.
  - 원문을 고치는 방법은 다른 문장에서 같은 일이 다시 생길 수 있어 고르지 않았습니다.

## 영향

- `npm ci`가 받는 패키지가 82개 늘어납니다.
- 구현할 때 빌드 결과에서 `/work`의 클라이언트 JS가 늘지 않았는지 확인합니다.
- F4 `/resume`도 같은 컴포넌트를 씁니다.
- `remark-cjk-friendly`로 패키지가 5개(약 150KB) 더 늘어납니다. 빌드 때만 돌아서 방문자 쪽 비용은 없습니다.
