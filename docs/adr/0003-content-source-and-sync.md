# ADR-0003: 콘텐츠 원본은 이력서·포트폴리오 md이고, 허용 목록으로 동기화한다

- 상태: 채택 (동기화 스크립트는 1차에서 구현, 구현 원칙과 원본에 없는 작업 2026-10-14 추가, Recueve는 2026-10-15 원본에 들어와 원본에 없는 작업에서 뺌, 첫 화면 기술 층의 짝은 2026-10-16부터 ADR-0010)
- 날짜: 2026-10-14

## 배경

이력서와 포트폴리오는 이미 md 원본에서 PDF를 만들어 쓰고 있습니다. 홈페이지에 같은 내용을 다시 쓰면 세 벌이 생기고, 수치나 날짜가 하나씩 어긋나기 시작합니다.

원본이 있는 커리어 저장소는 비공개입니다. 공개하면 안 되는 개인 문서도 함께 들어 있습니다.

## 검토한 안

| 안 | 장점 | 단점 |
|---|---|---|
| 홈페이지를 커리어 저장소 안에 둔다 | 원본을 바로 읽는다 | 저장소를 공개할 수 없다. 배포 서비스가 비공개 문서 전체에 접근한다 |
| 사이트용 글을 따로 쓴다 | 단순하다 | 내용이 세 벌이 되어 어긋난다 |
| 별도 저장소 + 허용 목록 동기화 | 원본은 하나, 저장소는 공개 가능 | 동기화 스크립트가 필요하다 |

## 결정

- 홈페이지는 별도 공개 저장소로 둡니다.
- `npm run sync`가 커리어 저장소에서 **허용 목록에 있는 파일만** 가져와 `content/synced/`에 씁니다. 허용 목록 밖의 파일은 읽지 않습니다.
- 가져올 때 연락처 표에서 전화번호를 지웁니다. 그 뒤 민감정보 검사를 한 번 더 돌립니다.
- 원본 저장소 경로는 환경변수 `CAREER_DIR`(`.env.local`, git 제외)로 받습니다. 코드에 경로를 적지 않습니다.
- `content/synced/`는 커밋합니다. 원본 저장소가 없어도 누구나 빌드할 수 있고, 배포 서비스는 공개 저장소만 봅니다.
- 사이트에서만 쓰는 글(한 줄 소개, AI 작업 카드, 원본에 없는 작업 소개)은 `content/site/`에 직접 씁니다.

## 구현 원칙

동기화 스크립트를 만들기 전에 정했습니다(2026-10-14).

### 공개 범위가 다른 내용

- 이 저장소 작업 때문에 원본을 고치지 않습니다. 공개 페이지에 맞게 빼거나 고칠 내용은 모두 동기화 규칙으로 처리합니다. 원본 문서에만 맞는 문구도, 틀렸거나 근거가 약한 내용도 같습니다.
- 원본에도 반영할 만한 수정은 원본 저장소의 `docs/todo/`에 남깁니다. 원본에 반영할지는 그쪽에서 정합니다.
- 동기화 규칙은 공개 저장소에 들어가므로 값이 아니라 항목 이름으로 찾습니다. 찾던 대상이 원본에 없으면 동기화를 멈춥니다. 원본에 수정이 반영되면 이렇게 멈추므로, 그때 해당 규칙을 지웁니다.
- 전화번호는 연락처 표에서 머리글이 `전화번호`인 열을 통째로 지웁니다.
- 허용 목록과 변환 규칙은 `scripts/sync.config.mjs` 한 파일에 둡니다. 무엇을 공개하는지가 이 파일의 diff로 보입니다.

### 쓰기 전에 막기

- 변환 결과를 파일에 쓰기 전에 민감정보 규칙과 비공개 금지어로 검사합니다. 한 건이라도 걸리면 아무 파일도 쓰지 않습니다. 검사 규칙은 `check:sensitive`와 같은 모듈을 씁니다.
- 비공개 금지어 목록(`.sensitive-terms.local`)이 없으면 실행하지 않습니다. 빈 파일은 일부러 비운 것으로 보고 허용합니다.
- 허용 목록의 파일이 없거나 링크로 원본 저장소 밖을 가리키면 건너뛰지 않고 멈춥니다.
- 오류 메시지에는 원본 내용을 그대로 찍지 않습니다.

### 원본과 결과의 대응

- 원본 저장소에 커밋하지 않은 변경이 있으면 실행하지 않습니다. 미리 보기용 `--allow-dirty`로 실행하면 그 사실이 manifest에 남습니다.
- manifest(`content/synced/manifest.json`)에는 원본 커밋 해시, 커밋 안 된 변경 여부, 출력 파일 목록, 적용한 변환만 적습니다. 원본 파일의 해시와 경로는 적지 않습니다. 결과와 원본은 지운 값만 다르므로, 원본 해시가 공개되면 지운 값을 하나씩 대입해 맞춰 볼 수 있기 때문입니다. 전화번호는 경우의 수가 1억 개뿐이라 몇 초면 됩니다.
- `content/synced/`는 동기화 스크립트가 전부 맡습니다. 매번 비우고 다시 써서 허용 목록에서 뺀 파일이 남지 않게 합니다.
- `npm run sync -- --check`는 파일을 쓰지 않고 `content/synced/`가 원본에서 다시 만든 결과와 같은지만 확인합니다.

### 원본에 없는 작업

사이트에서 소개하는 작업 중 이력서와 포트폴리오에 없는 것은 `content/site/`에 사이트 전용 글로 씁니다.

| 작업 | 글 |
|---|---|
| Brain House, AI TOOLS | `content/site/sites/` |
| Jake Wiki, 영상 제작, Jake Hermes | `content/site/ai/` |

- 이 글에는 공개된 곳(라이브 사이트, 공개 저장소, 공개 영상)에서 확인할 수 있는 사실과 제가 확인한 사실(기간, 역할, 스택, 만든 방법)만 넣습니다.
- 공개하지 않는 자료(개인 위키의 내용 등)는 방법만 쓰고, 내용과 화면은 싣지 않습니다.
- 원본에 같은 내용이 없으므로 여러 벌이 어긋나는 문제는 생기지 않습니다.

### 판단

AI는 독자에 따라 다른 내용만 동기화 규칙으로 빼고, 틀렸거나 근거가 약한 내용은 원본에서 고치자고 제안했습니다. 원본을 하나로 두자는 취지였습니다. 저는 원본은 고치지 않고 사이트에 맞는 내용을 따로 쓰기로 했습니다. 사이트에 맞게 고친 내용은 원본 저장소의 할 일로 넘겨, 원본에 반영할지는 그쪽에서 따로 정합니다.

## 영향

- 이력서·포트폴리오에서 온 내용을 사이트에서 바꿀 때는 동기화 규칙을 더합니다. 원본과 `content/synced/`는 직접 고치지 않습니다.
- 동기화 결과의 변경분이 커밋 diff로 보이므로, 무엇이 공개되는지 커밋할 때마다 확인할 수 있습니다.
