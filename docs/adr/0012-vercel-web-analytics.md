# ADR-0012: 방문 통계는 Vercel Web Analytics로 익명으로 센다

- 상태: 채택
- 날짜: 2026-10-24

## 배경

사이트를 공개한 뒤 어느 페이지를 얼마나 보는지, 어디서 들어오는지 알 수 없습니다. 지금 볼 수 있는 것은 Vercel의 요청 로그뿐인데, 검색엔진과 미리보기 봇의 요청이 섞여 있어 사람의 방문으로 읽을 수 없습니다.

[ADR-0002](0002-personal-hub-for-everyone.md)는 방문 통계를 "페이지 단위의 익명 통계까지만" 쓰기로 했습니다. 페이지 조회만으로는 첫 화면의 서비스 세 개 중 무엇을 열어 보는지가 보이지 않습니다.

## 검토한 안

요금과 수집 항목은 Vercel 문서의 Web Analytics 요금, 개인정보, 커스텀 이벤트 페이지로 확인했습니다(2026-10-24).

| 안 | 장점 | 단점 |
|---|---|---|
| Vercel 요청 로그만 본다 | 더할 것이 없습니다 | 봇 요청이 섞이고, 링크를 누른 것은 보이지 않습니다 |
| Google Analytics | 무료이고 기능이 많습니다 | 쿠키로 방문자를 알아보고 사람별 흐름을 따라갑니다. ADR-0002의 익명 기준에서 벗어나고, 알림과 동의 절차가 따라옵니다 |
| Plausible, Umami | 쿠키 없이 셉니다 | 직접 운영하면 서버와 데이터베이스가, 호스팅을 쓰면 월 요금이 따로 생깁니다 |
| Vercel Web Analytics | 이미 배포하는 Vercel에서 켜면 됩니다. 쿠키를 쓰지 않습니다. 이 사이트의 Vercel 팀은 Pro 요금제라 링크 클릭(커스텀 이벤트)도 셀 수 있습니다 | 이벤트 1,000건마다 0.03달러가 나갑니다(Pro 사용 크레딧에서 먼저 씀). 통계는 Vercel 대시보드에서만 보고, 보관은 12개월입니다 |

## 판단

AI는 Vercel Web Analytics를 추천했습니다. 배포에 쓰는 서비스 안에서 끝나 운영할 것이 늘지 않고, 쿠키 없이 익명으로 세어 ADR-0002의 방향과 맞기 때문입니다.

AI는 ADR-0002 그대로 페이지 조회만 세자고 추천했습니다. 저는 어느 서비스를 열어 보는지까지 보려고 바깥 링크 클릭도 세기로 했습니다. 클릭도 방문자를 식별하지 않고 횟수만 세므로, ADR-0002가 막은 방문자별 열람 기록과는 다릅니다.

사이트에 통계를 쓴다고 알리는 문구는 두지 않기로 했습니다. 쿠키와 개인 식별이 없어서입니다(AI 추천과 같음).

## 결정

- Vercel Web Analytics를 켜고 `@vercel/analytics`를 더합니다. MIT 라이선스이고 다른 패키지에 기대지 않습니다.
- 세는 것
  - 페이지 조회: 페이지를 열 때와 사이트 안에서 페이지를 옮길 때 패키지가 자동으로 셉니다.
  - 바깥 링크 클릭: 사이트 밖으로 나가는 링크(서비스 라이브 주소, GitHub 등)와 이메일 링크를 누르면 커스텀 이벤트를 하나 보냅니다. 목적지와 누른 페이지만 담습니다. 링크마다 코드를 달지 않고 한곳에서 잡습니다.
- 세지 않는 것: 방문자 식별, 사람별 흐름, 스크롤과 머문 시간, 입력값.
- 쿠키를 쓰지 않습니다. Vercel은 방문자를 요청에서 만든 해시로 구분하고 24시간 뒤 버립니다. 남는 것은 주소, 들어온 곳, 지역, OS, 브라우저, 기기 종류입니다.
- 통계는 Vercel 대시보드에서만 보고 사이트에 싣지 않습니다. 사이트에 따로 알리지 않습니다.
- ADR-0002의 "페이지 단위의 익명 통계까지만"을 "페이지 조회와 바깥 링크 클릭의 익명 집계까지만"으로 넓힙니다.

## 영향

- Vercel 대시보드에서 이 프로젝트의 Web Analytics를 켭니다.
- 뿌리 레이아웃에 통계 컴포넌트와 바깥 링크 클릭을 잡는 작은 클라이언트 컴포넌트를 더합니다. 구현은 feature 브랜치에서 합니다.
- E2E는 400 이상 응답을 오류로 셉니다. 로컬 빌드에는 Vercel이 주는 통계 스크립트 경로가 없으므로, Vercel 밖(로컬, E2E, CI)에서 스크립트를 넣지 않는 방법을 구현 계획에서 정합니다.
- 이벤트 요금은 같은 Vercel 팀의 사용 크레딧에서 나갑니다.
- [PRD](../01-prd.md) 1차 추가 요청과 비기능 요구사항의 개인정보 줄에 반영했습니다.
