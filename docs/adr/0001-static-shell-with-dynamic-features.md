# ADR-0001: 정적 사이트로 끝내지 않고, 정적 셸에 동적 기능을 더한다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

이미 포트폴리오 문서(md, HTML, PDF)가 있습니다. 이것을 홈페이지로 옮기는 가장 빠른 방법은 정적 페이지로 배포하는 것입니다.

## 검토한 안

| 안 | 내용 | 비용 |
|---|---|---|
| A | 포트폴리오 HTML을 다듬어 정적으로 배포 | 반나절 |
| B | Next.js 정적 내보내기. md를 읽어 페이지 생성 | 1~2일 |
| C | Next.js. 콘텐츠는 정적 셸, 의미 있는 부분에만 동적 기능 | 단계별 |

AI의 첫 제안은 A로 시작해 필요하면 B로 가는 것이었습니다. 정적 사이트로 충분하고 서버가 필요 없다는 이유였습니다.

## 판단

홈페이지 자체가 기술을 보여 주는 결과물입니다. Next.js를 쓰면서 정적 페이지만 있으면 그 기술을 고른 이유가 드러나지 않습니다. 반대로 홈페이지에 백엔드와 DB를 붙이는 것은 과설계입니다. 백엔드 역량은 운영 중인 서비스들이 이미 보여 줍니다.

## 결정

C안으로 갑니다.

- 콘텐츠 페이지(홈, 프로젝트 상세, 이력서)는 사전 렌더링한 정적 셸로 보냅니다.
- 동적 기능은 이력과 직접 이어지는 것만 넣습니다. 질문 창(F7), GENYS Lotto AI 라이브 카드(F8), GitHub 활동 카드(F9)입니다.
- 별도 서버와 DB는 두지 않습니다. Route Handler와 관리형 서비스(요청 제한용 Redis 등)로 해결합니다.

## 영향

- 2차 기능마다 외부 서비스가 하나씩 늘 수 있습니다. 추가할 때마다 ADR을 남깁니다.
- 동적 부분이 실패해도 정적 셸은 그대로 보여야 합니다.
