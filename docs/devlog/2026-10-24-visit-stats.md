# 2026-10-24 방문 통계

## 한 일

- 방문 통계를 PRD 1차 추가 요청으로 넣고, 도구와 범위를 [ADR-0012](../adr/0012-vercel-web-analytics.md)로 정했습니다. [ADR-0002](../adr/0002-personal-hub-for-everyone.md)의 "페이지 단위 익명 통계"를 바깥 링크 클릭까지 넓혔습니다.
- `@vercel/analytics`(2.0.1)를 더했습니다. 페이지 조회는 패키지가 세고, 바깥 링크와 이메일 링크 클릭은 문서 전체의 클릭을 한곳에서 잡아 `outbound` 이벤트로 보냅니다(`src/components/outbound-clicks.tsx`, `src/lib/outbound.mjs`). 이벤트에는 목적지와 누른 페이지만 담고, 이메일 주소는 보내지 않습니다.
- 통계는 Vercel 운영 배포에서만 넣습니다(`src/components/site-analytics.tsx`). 로컬과 CI의 빌드에는 통계 스크립트 경로가 없어 404가 나고, E2E는 400 이상 응답을 오류로 셉니다.
- Vercel 대시보드에서 이 프로젝트의 Web Analytics는 직접 켰습니다. 요금 선택에서는 기본 Web Analytics를 골랐습니다.

## 바로잡은 것

- 시험에 `tel:` 링크 예로 휴대전화 번호 모양의 값을 넣었다가 민감정보 검사에 걸렸습니다. 번호 모양이 아닌 값으로 바꿨습니다.

## 검증

- `npm test` 136개 통과(새 `outbound` 시험 7개 포함), `npm run verify` 11개 통과. 통계가 들어가지 않는 빌드라 E2E와 캡처는 그대로입니다.
- `VERCEL_ENV=production`으로 빌드해 `ensureStatic = "navigation"` 검사를 통과하는지 봤습니다. 그 빌드를 띄우고 Playwright로 다음을 확인했습니다.
  - 통계 스크립트를 요청합니다. 로컬이라 404입니다.
  - 홈을 열면 페이지 조회가 하나 쌓입니다.
  - 서비스 링크, GitHub, 이메일, 가운데 버튼으로 연 서비스 링크마다 `outbound` 이벤트가 하나씩 쌓입니다.
  - 사이트 안 링크로 옮기면 페이지 조회만 쌓입니다.
- 홈에서 내려받는 JS는 151.8KB에서 152.1KB가 됐습니다. 운영에서는 Vercel의 통계 스크립트가 따로 붙습니다.
