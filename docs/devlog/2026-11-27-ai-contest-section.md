# 2026-11-27 `/ai` 대회 참가 결과 묶음

## 한 일

- `/ai` 맨 끝에 다섯째 묶음 "대회 참가 결과"를 더했습니다. AX인재전쟁 카드 하나를 두고, "자세히 보기"로 `/ai/axwar`에 갑니다. 맨 위 목차는 데스크톱에서 다섯 칸이 됐습니다.
- 카드는 ProWith 하네스, Recueve AI 자동 채움과 같은 짧은 카드입니다. 글은 `/ai/axwar`의 본문과 덧붙임 줄을 줄인 것이고 새 사실은 없습니다. 숫자 칸과 문장 조각은 내용 시험이 `/ai/axwar` 글과 대조합니다.
- `/ai/axwar` 끝 버튼 줄에 채운 버튼 "인증서 보기 ↗"를 되살렸습니다. 머리 아래 인증서 카드는 그대로입니다.
- 대회 결과 띠의 시험이 두 줄을 함께 보고, "2일 만에"처럼 숫자로 쓴 기간도 막습니다.
- `/ai/axwar`를 만들며 겪은 일 두 가지를 가이드에 남겼습니다. 새 페이지의 E2E는 응답 200부터 보고([검색과 공유](../guide/SEO_검색과_공유_정책_20261017.md)), 바깥 증빙은 공유 그림을 저장소에 받아 둔 링크 카드로 보입니다([AI 사례](../guide/CONTENT_AI_사례_20261020.md)).
- 정한 것과 비교한 안은 [IA](../02-ia.md#ai-ai로-일하는-방식-f3)에, 설계는 [specs](../superpowers/specs/2026-11-27-ai-contest-section-design.md)에 있습니다.

## 바로잡은 것

- 개발 서버에 대고 E2E를 돌리는 설정의 주소를 `127.0.0.1`로 두었더니, 바꾸지 않은 페이지까지 모든 맨 위로 버튼 시험이 실패했습니다. Next.js 개발 서버는 시작한 호스트(`localhost`) 밖의 출처에서 오는 개발용 요청을 막습니다(`allowedDevOrigins`). 주소를 `localhost`로 바꾸자 모두 통과했습니다. 빌드한 사이트로 도는 `npm run verify`와는 상관없습니다.
- 짧은 카드 시험이 `/ai/axwar`에 도착했는지를 h1이 보이는지로만 봐서, 없는 페이지(404 화면에도 h1이 있음)로 가도 통과했습니다. 이 작업에서 가이드에 남긴 "새 페이지의 E2E는 응답 200부터"와 어긋나, 최종 리뷰에서 찾았습니다. 주소를 없는 페이지로 바꿔 통과하는 것을 본 뒤, 응답이 200인지 먼저 보게 고쳐 실패를 확인하고 되돌렸습니다.

## 검증

- 시험을 먼저 고치고 실패를 본 뒤 구현했습니다. 카드가 없을 때 내용 시험이, 목차가 네 칸일 때 다섯째 칸이 둘째 줄로 내려가 E2E가, 끝 줄에 인증서 버튼이 없을 때 `/ai/axwar` 끝 줄 시험이 실패했습니다.
- `npm run verify`: 11개 중 9개 통과, 2개 실패입니다. E2E는 312개 통과, 화면 캡처는 30장입니다. 실패한 둘은 로컬 전용 검사(동기화 확인, 기술 층 확인)로, main에서도 똑같이 나는 기존 실패라 이 작업에서 고치지 않았습니다.
