# 2026-10-20 AI 도구 활용 사례 페이지 기획

## 한 일

- 커리어 저장소에서 PDF로 만든 AI 도구 활용 사례(4컷과 본문)를 사이트에 싣는 방법을 질문 라운드로 정했습니다. `/ai` 아래의 서브페이지 `/ai/case`에 두고, `/ai` 맨 위에 입구를 둡니다. 정한 내용은 [02-ia.md](../02-ia.md#aicase-ai-도구-활용-사례)와 [03-design.md](../03-design.md#ai-사례에서-정한-값)에 있습니다.
- 개발 서버의 `/ai`에 시안을 얹어 입구 세 안, 4컷 배치 세 안, 다크 모드 세 안을 비교판으로 골랐습니다. 캡처는 [docs/design/ai-case/](../design/ai-case/)에 있습니다.
- 사례의 원본(txt, json, png)을 동기화로 가져오도록 [ADR-0003](../adr/0003-content-source-and-sync.md#원본-추가-ai-도구-활용-사례-2026-10-20)을 넓혔습니다.

## 바로잡은 것

- **사례의 요지를 프로젝트 이름으로 읽은 것**: 4컷이 셋업, 사양 정리, 검증, 기록이라는 프로젝트 전체 단계를 보여 주는데, AI가 처음에 ProWith 하네스 항목으로 다뤄 기존 카드와 겹치는지부터 물었습니다. 사례가 무엇을 보여 주려는지 먼저 정하고 자리를 묻는 순서로 바꿨습니다.
- **설명 없이 쓴 화면 이름**: "하네스 짧은 카드"를 어디의 무엇인지 말하지 않고 질문에 써서 다시 물어야 했습니다. 질문에 화면 요소를 꺼낼 때는 주소와 지금 모양을 함께 적습니다.
- **원본과 포트폴리오가 엇갈리는 문장**: 사례는 DNS 설정도 AI 브라우저로 처리한다고 쓰지만, 포트폴리오에는 "직접 하는 건 DNS 설정 정도입니다"가 남아 있습니다. `/work`가 포트폴리오를 그대로 그려 한 사이트 안에서 말이 엇갈리므로, 원본 저장소의 할 일로 넘겼습니다.
- **그림의 흰 테두리**: 원본 칸을 그대로 자르면 1px 흰 여백과 둥근 모서리 바깥이 남아 다크 모드에서 흰 테두리로 보였습니다. 칸마다 안쪽으로 8px 더 자르기로 정했습니다.

## 검증

- 시안은 개발 서버의 `/ai`에 CSS와 마크업을 얹어 Playwright로 1280과 375, 라이트와 다크를 찍었습니다.
- 본문의 사실 가운데 포트폴리오에 없는 것을 각 서비스의 코드와 문서로 확인했습니다. 신규 업체 셋업 스킬에 Vercel과 등록사 DNS를 브라우저 자동화로 다루는 단계가 있고, Recueve 관리자 화면 가이드가 ProWith의 표 가이드(정렬, 페이지네이션, 합계 행)를 가져다 쓴다고 적고 있습니다. 가이드 문서는 오늘 세면 ProWith 72개, Recueve 60개(README 제외)이고, 사례 본문은 71개, 60개입니다. 어떻게 쓸지는 원본 저장소에서 정합니다.
