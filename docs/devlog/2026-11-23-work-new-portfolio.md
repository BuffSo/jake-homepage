# 2026-11-23 /work를 새 포트폴리오 원본에 맞추기

## 한 일

- 포트폴리오 원본의 구성이 바뀌어(프로젝트 상세가 앞, 프로젝트마다 구성도, Jake English 추가, 「보시는 방법」 절이 표의 한 칸으로) `/work`가 원문을 읽는 방식을 새 형식에 맞췄습니다. 화면 모양은 그대로이고 챕터가 넷이 되었습니다.
- 원문의 그림 다섯 장(구성도 넷, Recueve 자동 채우기 흐름도)을 원문 자리에 실었습니다. 좁은 화면에서는 그림만 상자 안에서 옆으로 넘깁니다.
- 원본이 인쇄본 분량에 맞춰 뺀 상세(「기술적 결정」 표 둘, ProWith 쇼핑몰과 설정 엔진, GENYS Lotto AI의 로그 저장소와 계정 전환기)를 동기화 규칙으로 사이트에만 남겼습니다.
- 사이트 전용 글을 원본의 새 표현에 맞췄습니다(Recueve 기간, ProWith 하네스 카드의 문구와 이름, 근거 줄 열 개, Jake English 영상 주소).
- 정한 것은 [IA](../02-ia.md)의 `/work` 절에, 값은 [디자인 문서](../03-design.md)의 「원문 그림과 긴 첫 칸 표」에, 설계는 [specs](../superpowers/specs/2026-11-23-work-new-portfolio-design.md)에, 원본 구성이 바뀔 때의 순서와 겪은 문제는 [가이드](../guide/CONTENT_포트폴리오_동기화_20261123.md)에 있습니다. 캡처는 `docs/design/work-new-portfolio/`에 있습니다.

## 바로잡은 것

- 처음에는 그림 묶음 전체를 옆으로 넘기게 해, 설명 줄까지 밀려 잘렸습니다. 넘기는 상자가 그림만 감싸도록 플러그인(`rehypeFigures`)으로 바꿨습니다.
- 「기술적 결정」 표를 넣고 화면을 보니 첫 칸이 한 줄로 늘어나 이유 칸이 네댓 글자 폭이었습니다. 표의 첫 칸은 줄을 바꾸지 않는 규칙 때문입니다. 첫 칸이 문장인 표만 고르는 플러그인을 더했고, 기준을 20자로 잡았다가 스킬 표까지 걸려 30자로 올렸습니다.
- E2E의 버튼 찾기가 Jake English에서 「보시는 방법」 글의 같은 이름 링크와 겹쳐 실패했습니다. 버튼만 보도록 고쳤습니다.
- 커밋 하나에 시험과 문서를 함께 넣었다가, 한 커밋에 type 하나라는 규칙대로 푸시 전에 둘로 나눴습니다.
- 겪은 문제의 원인과 막는 방법은 가이드에 적었습니다.

## 검증

- `npm run verify` 11개 통과, 건너뜀 없음(결과는 PR 본문의 표).
- 단위 시험은 새 형식의 가짜 원본으로 다시 썼습니다. 주소가 여럿인 줄, 한눈에 보기 표, 뒤에 붙는 절과 번호 떼기, 형식이 다를 때 멈추는 경우, 동기화 규칙이 제자리에 끼우고 자리가 없으면 멈추는 것을 봅니다.
- E2E는 챕터 넷과 목차 다섯 칸, 그림 다섯 장, 모바일에서 그림 상자만 넘기고 페이지는 넘치지 않는 것, 사이트에만 남긴 블록의 제목을 봅니다.
- `/resume`은 1280과 375에서 Jake English 프로젝트 항목, 링크 줄, Recueve 기간을 눈으로 봤습니다.
