# 2026-11-17 짧은 주소 열 개로도 홈 열기

## 한 일

- 홈을 짧은 주소 열 개(`/about`, `/intro`, `/hello`, `/me`, `/profile`, `/welcome`, `/start`, `/info`, `/home`, `/main`)로도 엽니다. 어느 주소로 열어도 홈과 같은 화면이 나오고 주소창은 그대로입니다. 방문 통계에는 주소마다 따로 잡혀, 링크를 둔 곳마다 다른 주소를 쓰면 어디서 들어왔는지 나눠 볼 수 있습니다.
- 경로 묶음 폴더 `src/app/(home-aliases)/` 아래에 주소마다 정적 페이지를 두고, 각 페이지는 홈을 그대로 내보냅니다. 대표 주소와 공유 정보는 홈의 것이고, 사이트맵에는 넣지 않았습니다. 정하지 않은 주소는 지금처럼 빌드 때 만든 404입니다.
- 규칙과 방법을 고른 이유는 [검색과 공유 정책](../guide/SEO_검색과_공유_정책_20261017.md)의 "같은 화면을 다른 주소로도 열 때"에, 통계가 어느 경로로 잡히는지는 [방문 통계](../guide/ANALYTICS_방문_통계_20261024.md)에 있습니다. 설계는 [specs](../superpowers/specs/2026-11-17-home-alias-paths-design.md)에 있습니다.

## 흐름

| # | AI 제안 | 판단 | 결과 |
|---|---|---|---|
| 1 | - | 사용자가 주소 열 개, 넘기지 않기, 주소마다 통계, 대표 주소는 홈, 사이트맵 제외를 정했다 | 화면이 바뀌지 않아 비교판 없이 설계부터 함 |
| 2 | (main 세션) `[alias]` 동적 페이지 하나에 `generateStaticParams`로 열 개를 만들고 `dynamicParams = false`로 나머지를 404로 두자 | 설계에서 Next 문서를 보니 `cacheComponents`를 켜면 `dynamicParams`를 쓸 수 없다. 그대로 두면 모르는 한 단계 주소가 첫 요청 때 서버에서 그려진 뒤 404가 된다 | 세 방법(`rewrites`, `[alias]`와 `notFound()`, 정적 페이지 열 개)을 비교함 |
| 3 | 정적 페이지 열 개를 추천. `rewrites`는 서버가 그린 경로와 브라우저 경로가 달라 헤더 메뉴처럼 경로를 읽는 곳이 수화 오류를 낼 수 있다 | 사용자가 정적 페이지 열 개를 골랐다 | 서버와 브라우저의 경로가 같고 모르는 주소는 그대로 404 |
| 4 | 열 개를 괄호 폴더에 모으고, `noindex`는 달지 않고(대표 주소와 함께 달면 신호가 엇갈림), 시험은 데스크톱 E2E 파일 하나로 두자 | 사용자가 그대로 승인했다 | 설계 문서에 에이전트 판단으로 적음 |
| 5 | 방문 통계가 주소마다 따로 잡히는지는 `@vercel/analytics` 코드와 운영 통계 스크립트를 읽어 확인하자 | 같음 | 페이지 조회는 `usePathname()` 값으로 보내서 `/about`이 따로 잡힘. 운영 확인은 배포 뒤에 함 |

## 바로잡은 것

- 시험에서 다음 페이지 버튼을 이름(`getByRole`)으로 찾았는데, 이 버튼은 페이지 끝까지 내리기 전에는 `hidden`이라 이름이 계산되지 않아 찾지 못했습니다. 홈에서도 똑같이 실패하는 찾기였습니다. `main` 바로 뒤의 버튼 칸에서 찾고 주소와 글을 함께 보게 고쳤습니다.

## 검증

- `npm run verify` 11개 통과, 건너뜀 없음(결과는 PR 본문의 표).
- 새 E2E `e2e/home-aliases.spec.ts` 15개: 폴더 이름이 정한 열 개와 같음, 주소마다 200과 주소 그대로, 콘솔 오류 없음, 제목·본문 글·JSON-LD·대표 주소·공유 그림이 홈과 같음, 메뉴 표시 없음, 다음 페이지가 `/work`. 끝 슬래시와 쿼리, 봇 User-Agent 200, `/abcd`·`/About`·`/about/more` 404, 짧은 주소에서 메뉴로 이동.
- 페이지를 만들기 전에 이 시험을 돌려, 폴더 시험은 폴더가 없어서, 주소 시험은 404로 실패하는 것을 먼저 봤습니다.
