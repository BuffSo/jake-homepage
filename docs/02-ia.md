## 홈

### 1. 첫 화면

| 항목 | 내용 |
|---|---|
| 메시지 | 기획부터 디자인, 개발, 배포까지 전 과정을 다루고, 속도는 AI로 내되 판단과 검증은 AI 이전부터 쌓은 경험으로 합니다 |
| 사실과 출처 | 첫 줄, 둘째 줄, 보조 문장, 기술 층 여섯 개, 서비스 세 개 증거 목록, 이메일과 GitHub. 재료와 출처는 [04-motion.md](04-motion.md#재료) |
| 문구 초안 | 첫 줄 "Idea to production." · 둘째 줄 "기획부터 디자인, 개발, 배포까지 전 과정을 다룹니다." · 보조 문장 "속도는 AI로 내고, 판단과 검증은 AI 이전부터 쌓은 경험으로 합니다." |
| 움직임 | 있음. 다섯 박자, [04-motion.md](04-motion.md) |

이력서의 한 줄 소개 "AI를 더해 기술을 비즈니스 가치로 연결하는 풀스택 개발자"는 첫 화면 글이 세 줄을 넘지 않도록 첫 화면에서는 빼고, 경력 섹션과 `/resume`에서 씁니다.

서비스 세 개는 첫 화면의 주인공이 아니라 증거입니다. 큰 카드가 아니라 이름, 한 줄 설명, 라이브 링크만 담은 작은 목록으로 둡니다.

### 2. 운영 중인 서비스

| 항목 | 내용 |
|---|---|
| 메시지 | 세 서비스 모두 지금 열어 보실 수 있습니다 |
| 사실과 출처 | 서비스, 한 줄 설명, 역할, 기간, 스택(포트폴리오 "1. 한눈에 보기"), 보는 방법(포트폴리오 "보시는 방법"). Recueve는 `content/site/projects/recueve.md` |
| 문구 초안 | 제목 "운영 중인 서비스" · 소개 "직접 설계하고 개발해 배포한 서비스 세 개입니다. 세 곳 모두 지금 열어 보실 수 있습니다." |
| 움직임 | 없음 |

카드마다 상세 페이지(`/work/[slug]`)와 라이브 서비스로 연결합니다.

제목 위 작은 머리 문구 후보로 "Planned, designed, built, shipped."를 둡니다. 첫 화면 제목으로는 길어서 빼 둔 문구입니다. 세 서비스가 모두 이 네 단계를 거쳐 지금 운영 중이라는 뜻이라, 이 섹션에서는 섹션 제목을 받쳐 주는 역할을 합니다.

카드 대신 기술과 서비스 표(층이 열, 서비스가 행이고 쓴 기술이 칸으로 보이는 형태, F1 스토리보드의 배치 C)를 쓰는 안도 후보입니다. 두 후보 모두 섹션을 구현할 때 쓸지 정합니다.

### 3. AI로 일하는 방식

| 항목 | 내용 |
|---|---|
| 메시지 | 구현은 AI를 활용해 빠르게 하고, 기준과 판단은 제가 정해 장치로 고정합니다 |
| 사실과 출처 | 포트폴리오 "2. AI 활용 - 개발"(스킬 6종, 검사 두 가지), `content/site/projects/recueve.md`의 "AI 자동 채움"(Recueve), 이 저장소(CLAUDE.md, 훅, CI, ADR, devlog) |
| 문구 초안 | 제목 "AI로 일하는 방식" · 소개 "구현은 AI를 활용해 빠르게 하고, 저는 기준을 정하고 판단과 검증에 집중합니다. 이 사이트도 그렇게 만들었습니다." |
| 움직임 | 없음. 이 사이트가 만들어지는 과정(기획 문서 → 결정 → 구현 → 검사 → 기록)을 움직이지 않는 도식으로 보여 줍니다 |

도식 아래에 대표 AI 작업 카드 세 개와 `/ai` 링크를 둡니다.

"하네스 엔지니어링"이라는 말은 첫 화면에서 빼고 이 섹션에서 씁니다. 처음 보는 사람도 알 수 있게, AI가 지켜야 할 기준을 훅, 검사, CI 같은 장치로 고정하는 일이라고 풀어 씁니다.

## 공통 요소

- **헤더** - 이름, Work, AI, Resume
- **푸터** - 이메일, GitHub, "이 사이트의 소스"(이 저장소)
- **질문 창** (2차) - 모든 페이지에서 열 수 있는 패널

## 콘텐츠 흐름

```
비공개 커리어 저장소 (원본 md)
  │  npm run sync  (허용 목록, 동기화 규칙)
  ▼
content/synced/    ← 동기화 결과. 직접 고치지 않는다. 커밋한다.
content/site/      ← 이 사이트에서만 쓰는 글 (문구 초안, AI 작업 카드 등)
  │  빌드할 때 파싱
  ▼
페이지
```

`content/synced/`가 커밋돼 있으므로 원본 저장소가 없어도 누구나 빌드할 수 있습니다. 자세한 이유는 [ADR-0003](adr/0003-content-source-and-sync.md)에 있습니다.

## 콘텐츠 모델 (초안)

```ts
type Project = {
  slug: "recueve" | "prowith" | "lotto-ai";
  title: string;
  summary: string;        // 한 줄 설명
  period: string;         // 예: "2026.04 ~ 2026.05"
  role: string;           // 예: "풀스택 (회사)"
  stack: string[];
  liveUrl: string;
  howToView?: string;     // "보시는 방법" 안내
  body: string;           // 상세 본문 (md)
};

type StackLayer = {
  name: "화면" | "API" | "워커" | "데이터" | "인프라" | "AI";
  items: string[];        // 최대 세 개
  usedBy: Project["slug"][];
};

type AiCard = {
  slug: string;
  title: string;
  problem: string;        // 무엇이 문제였나
  built: string;          // 무엇을 만들었나
  result: string;         // 무엇이 달라졌나 (확인 가능한 근거)
  links: { label: string; href: string }[];
};

type CareerItem = {
  org: string;
  role: string;
  period: string;
  summary: string;
};
```

필드는 1차 구현 때 확정하고 이 문서를 고칩니다.
