# 02. 정보 구조 (IA)

- 상태: 초안 (2026-10-14). 홈 구성은 F1 기획에서 정했습니다(아래 "홈 시안").

## 페이지

| 경로 | 내용 | 단계 |
|---|---|---|
| `/` | 홈(메인). 아래 섹션 순서 참고 | 1차 (F1) |
| `/work` | 포트폴리오. 세 서비스의 상세와 의뢰받아 만든 사이트 두 개. 서비스마다 페이지를 나눌지(`/work/[slug]`)는 F2 기획에서 정합니다 | 1차 (F2) |
| `/ai` · `/ai/[slug]` | AI 작업 목록과 상세 | 1차 (F3) |
| `/resume` | 이력서 (인쇄용) | 1차 (F4) |
| `/en/...` | 영어 페이지 | 2차 |

섹션과 페이지마다 전달할 메시지, 담을 사실과 출처, 문구 초안, 움직임을 적습니다. 사실의 출처는 `content/synced/`의 원본 절이고, 원본에 없는 작업(Recueve, 사이트 두 개, AI 작업)은 `content/site/`의 사이트 전용 글입니다(ADR-0003). 문구 초안은 구현하면서 다듬고, 바뀌면 이 문서를 고칩니다.

## 홈

홈은 만든 것을 짧게 보여 주고, 자세한 내용은 `/work`, `/ai`, `/resume`으로 보냅니다. 작업이 주인공이고 사람 소개는 짧게 뒤에 붙습니다([03-design.md](03-design.md#참고한-사이트)). 경력 목록은 홈에 두지 않고 About의 "이력서 보기"로 연결합니다.

순서: 첫 화면 → 운영 중인 서비스 → AI로 일하는 방식 → About → 푸터

섹션 머리는 작은 영어 라벨(Geist Mono)과 한국어 제목으로 맞춥니다. "Planned, designed, built, shipped."와 스토리보드 배치 C의 표는 쓰지 않습니다.

### 1. 첫 화면

| 항목 | 내용 |
|---|---|
| 메시지 | 기획부터 디자인, 개발, 배포까지 전 과정을 다루고, 속도는 AI로 내되 판단과 검증은 AI 이전부터 쌓은 경험으로 합니다 |
| 사실과 출처 | 첫 줄, 둘째 줄, 보조 문장, 기술 층 여섯 개, 서비스 세 개 목록, 이메일, GitHub, 이력서 보기. 재료와 출처는 [04-motion.md](04-motion.md#재료) |
| 문구 초안 | 첫 줄 "Idea to production." · 둘째 줄 "기획부터 디자인, 개발, 배포까지 전 과정을 다룹니다." · 보조 문장 "속도는 AI로 내고, 판단과 검증은 AI 이전부터 쌓은 경험으로 합니다." |
| 움직임 | 있음. 다섯 박자, [04-motion.md](04-motion.md) |

서비스 세 개는 첫 화면의 주인공이 아니라 증거입니다. 이름, 한 줄 설명, 라이브 링크만 담은 작은 목록으로 둡니다. 번호(01~03)는 아래 서비스 카드와 같고, 이름을 누르면 해당 카드로 내려갑니다.

### 3. AI로 일하는 방식

| 항목 | 내용 |
|---|---|
| 메시지 | 구현은 AI를 활용해 빠르게 하고, 기준은 장치로 고정합니다. 개발 밖의 일에도 같은 방식을 씁니다 |
| 사실과 출처 | `content/site/ai/`의 사이트 전용 글. "이 사이트" 카드는 이 저장소 |
| 구성 | 머리 `AI` · 제목 "AI로 일하는 방식" · 소개(메시지와 같음) · 카드 네 장. "자세히 보기"는 `/ai/[slug]` |
| 움직임 | 없음 |

| 카드 | 제목 문장 | 숫자 | 그림 |
|---|---|---|---|
| Jake Wiki | 자료를 넣으면 AI가 정리하는 위키를 씁니다. | 위키 30쪽 · 규칙 문서 5개 (2026.10 기준) | 흐름 도식(raw·clippings → Claude → wiki). 개인 위키라 내용과 화면은 싣지 않습니다 |
| 영상 제작 | 편집 도구를 배우지 않고 영상을 만들었습니다. | 71.9초 · 6장면 · 1080p | 유튜브 썸네일. computer use로 에이전트가 CapCut을 조작했고, 저는 목소리와 음악을 고르고 결과를 판단했습니다. 라이선스 때문에 음악을 바꾼 판단을 한 줄 넣습니다 |
| Jake Hermes | 텔레그램으로 일을 맡기는 개인 비서를 띄웠습니다. | 로컬 모델 · 예약 작업 2개 | 흐름 도식(텔레그램 ⇄ Hermes Agent ⇄ 로컬 모델, 예약 작업 · 조사 결과 알림). 정기 조사 결과가 메일로 오면 확인해 메시지로 알려 주는 개인 비서입니다. 예약 작업의 이름과 대상은 싣지 않습니다 |
| 이 사이트 | 이 사이트도 같은 방식으로 만들었습니다. | ADR 수 · CI 검사 수 (빌드할 때 저장소에서 셉니다) | 다섯 단계(기획 문서, 결정, 구현, 검사, 기록). 검사만 강조색입니다 |

"하네스 엔지니어링"이라는 말은 첫 화면에서 빼고 "이 사이트" 카드에서 씁니다. AI가 지켜야 할 기준을 훅, 검사, CI 같은 장치로 고정하는 일이라고 풀어 씁니다.

## 공통 요소

- **헤더** - 이름, Work(`/work`), AI(`/ai`), Resume(`/resume`). 모바일은 "메뉴" 버튼으로 같은 세 항목을 엽니다
- **본문으로 건너뛰기** - 키보드로 처음 Tab을 누르면 나타나 헤더를 건너뜁니다
- **푸터** - "© 2026 소재희", "이 사이트의 소스"(이 저장소)
- **질문 창** (2차) - 모든 페이지에서 열 수 있는 패널

## 콘텐츠 흐름

```
비공개 커리어 저장소 (원본 md)
  │  npm run sync  (허용 목록, 동기화 규칙)
  ▼
content/synced/    ← 동기화 결과. 직접 고치지 않는다. 커밋한다.
content/site/      ← 이 사이트에서만 쓰는 글 (원본에 없는 작업, AI 작업 등)
  │  빌드할 때 파싱
  ▼
페이지
```

`content/synced/`가 커밋돼 있으므로 원본 저장소가 없어도 누구나 빌드할 수 있습니다. 자세한 이유는 [ADR-0003](adr/0003-content-source-and-sync.md)에 있습니다.

## 콘텐츠 모델 (초안)

```ts
type Project = {
  slug: "recueve" | "prowith" | "lotto-ai";
  title: string;
  summary: string;        // 한 줄 설명
  headline: string;       // 홈 카드의 제목 문장
  period: string;         // 예: "2025.10 ~ 2025.11"
  role: string;           // 예: "풀스택 (개인)"
  stack: string[];
  metric: { value: string; label: string };
  liveUrl: string;
  howToView?: string;     // "보시는 방법" 안내
  body: string;           // 상세 본문 (md)
};

type Site = {
  slug: "brainhouse" | "aitools";
  title: string;
  headline: string;
  period: string;
  role: string;           // "외부 의뢰"
  stack: string[];
  metric: { value: string; label: string };
  liveUrl: string;
  sourceUrl: string;
};

type StackLayer = {
  name: "화면" | "API" | "워커" | "데이터" | "인프라" | "AI";
  items: string[];        // 최대 세 개
  usedBy: Project["slug"][];
};

type AiWork = {
  slug: string;
  title: string;
  headline: string;       // 홈 카드의 제목 문장
  problem: string;        // 무엇이 문제였나
  built: string;          // 무엇을 만들었나
  result: string;         // 무엇이 달라졌나 (확인 가능한 근거)
  metric: { value: string; label: string };
  links: { label: string; href: string }[];
};
```

필드는 1차 구현 때 확정하고 이 문서를 고칩니다.
