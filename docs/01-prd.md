# 01. 요구사항 (PRD)

- 상태: 초안 (2026-10-14)
- 관련: [00-vision.md](00-vision.md) · [02-ia.md](02-ia.md) · [03-design.md](03-design.md) · [04-motion.md](04-motion.md) · [adr/](adr/)

## 목표

1. 제가 무엇을 만들었고 어떻게 일하는지 한곳에서 보여 줍니다.
2. 이 저장소로 AI를 활용한 개발 과정(기획, 결정, 구현, 검증)을 보여 줍니다.

## 성공 기준

| 기준 | 확인 방법 |
|---|---|
| 첫 화면만 보고도 다루는 범위, 운영 중인 서비스 세 개, AI 활용 방식을 알 수 있다 | 화면 캡처 리뷰 |
| 사이트의 수치와 날짜가 이력서, 포트폴리오와 모두 같다 | 동기화 원본 대조 (F5) |
| 민감정보 노출 0건 | 커밋마다 `check:sensitive` 통과, CI 통과 |
| 모바일에서 가로 스크롤이 없다 | 375px 화면 캡처 |
| Lighthouse 성능과 접근성 90점 이상 | 배포 후 측정 |

## 범위

### 1차 (MVP)

| ID | 기능 | 수용 기준 |
|---|---|---|
| F1 | 홈 `/` | 첫 화면은 첫 줄과 짧은 움직임으로 시작해, 같은 화면 안에 소개 두 줄(다루는 범위와 일하는 방식), 기술 층 여섯 개, 서비스 세 개 증거 목록(이름, 한 줄 설명, 라이브 링크), 이메일과 GitHub가 남는다. 움직임은 [04-motion.md](04-motion.md)를 따르고, 움직임 줄이기 설정에서는 마지막 장면만 보인다. 이력서는 헤더와 About에서 연결한다(2026-10-17 첫 화면의 이력서 보기 링크를 뺐다). 그 아래에 운영 중인 서비스 카드 세 장, AI로 일하는 방식 카드 네 장, 짧은 About, 푸터가 이어진다([02-ia.md](02-ia.md#홈)). 경력 목록은 홈에 두지 않는다. 아래 섹션에는 움직임이 없다 |
| F2 | 포트폴리오 `/work` | Recueve, ProWith, GENYS Lotto AI의 상세(포트폴리오의 프로젝트 상세와 "보시는 방법")와, 의뢰받아 만든 사이트 두 개(Brain House, AI TOOLS)를 담는다. 서비스마다 페이지를 나눌지(`/work/[slug]`)는 F2 기획에서 정한다. 원본에 없는 작업은 사이트 전용 글(`content/site/`)을 쓴다 |
| F3 | AI로 일하는 방식 `/ai` | AI를 활용해 만든 것과 일하는 방식을 한 페이지에 싣는다: 이 사이트, 작업 환경, 코드 리뷰 스킬, ProWith 운영 하네스, Recueve AI 자동 채움, 영상 제작, 이미지 MCP, Jake Wiki, Jake Hermes. 항목마다 문제, 만든 것, 결과(확인 가능한 근거)를 쓴다. 원문이 `/work`에 있는 항목은 짧은 카드로 두고 `/work`로 보낸다 |
| F4 | 이력서 `/resume` | 이력서 md를 문장을 고치지 않고 그대로 그린다. 전화번호는 동기화에서 뺀다. 절 목차와 인쇄 버튼을 두고, 브라우저로 인쇄하면 A4로 깔끔하게 나온다. PDF 파일은 따로 올리지 않는다 |
| F5 | 콘텐츠 동기화 `npm run sync` | 허용 목록에 있는 원본 파일만 가져온다. 연락처 표에서 전화번호를 지운다. 결과를 `content/synced/`에 커밋한다([ADR-0003](adr/0003-content-source-and-sync.md)) |
| F6 | 검증 `npm run verify` | 타입체크, 린트, 테스트, 빌드, 민감정보 검사, 첫 화면 움직임 코드 용량(gzip 10KB 이하), 주요 화면 캡처를 한 번에 돌린다. 하나라도 실패하면 작업이 끝나지 않은 것이다. 실패해도 끝까지 돌리고 표로 요약하며, 빌드가 실패하면 빌드에 기대는 검사는 건너뛴다. 로컬 전용 검사(동기화 확인, 기술 층)는 경로가 없으면 건너뛴다. 캡처는 `test-results/captures/`에 남기고, 정한 캡처가 모두 생겼는지만 확인한다(픽셀 비교는 하지 않는다). CI는 검사를 단계별로 돌리고, 캡처는 통과해도 artifact로 올린다. verify의 검사 목록과 CI 단계가 같은지 테스트로 확인한다 |

네 페이지 모두 위쪽의 길잡이(홈은 첫 화면, 나머지 세 페이지는 목차)가 화면 위로 사라지면 맨 위로 가기 버튼이 보인다. 1차를 배포한 뒤 더한 요청이다(2026-10-17, [02-ia.md](02-ia.md#공통-요소)).

이력서 본문 끝, 푸터 위에 사진 한 장을 둔다. 캡션은 달지 않고 인쇄에서는 뺀다. 1차를 배포한 뒤 더한 요청이다(2026-10-17, [02-ia.md](02-ia.md#resume-이력서-f4)).

브라우저 탭과 홈 화면 아이콘(파비콘)을 사이트에 맞게 둔다. 1차를 배포한 뒤 더한 요청이다(2026-10-17, [02-ia.md](02-ia.md#공통-요소)).

검색과 공유에 필요한 정보를 둔다. 페이지마다 대표 주소(canonical)와 공유 정보(Open Graph, X 카드)를 두고, 모든 페이지가 미리보기 그림 한 장을 함께 쓴다. robots.txt는 검색엔진과 AI 크롤러를 모두 허용하고, 사이트맵에 네 페이지를 둔다. 홈에는 한 사람의 페이지임을 알리는 구조화 데이터(ProfilePage)를 둔다. 검색엔진 등록은 모든 기능이 완성된 뒤에 한다. 1차를 배포한 뒤 더한 요청이고, 2차 F11을 넓혀 앞당긴 것이다(2026-10-17, [검색과 공유 정책](guide/SEO_검색과_공유_정책_20261017.md)).

`/ai` 아래에 AI 도구 활용 사례 페이지(`/ai/case`)를 둔다. 프로젝트 하나(ProWith)를 셋업부터 사양 정리, 검증, 기록까지 AI와 진행한 흐름을 4컷과 본문으로 보여 준다. `/ai` 맨 위에 입구를 두고, 헤더 메뉴는 늘리지 않는다. 원본은 커리어 저장소의 사례 파일이고 동기화로 가져온다([ADR-0003](adr/0003-content-source-and-sync.md#원본-추가-ai-도구-활용-사례-2026-10-20)). 1차를 배포한 뒤 더한 요청이다(2026-10-20, [02-ia.md](02-ia.md#aicase-ai-도구-활용-사례)).

방문 통계를 본다. 페이지 조회 수와, 바깥으로 나가는 링크(서비스 라이브 주소, 이메일, GitHub 등)를 누른 횟수를 익명으로 센다. 쿠키를 쓰지 않고, 방문자를 식별하거나 사람별 기록을 남기지 않는다. 통계는 사이트에 싣지 않는다. [ADR-0002](adr/0002-personal-hub-for-everyone.md)의 "페이지 단위 익명 통계"를 링크 클릭까지 넓히는 것이고, 쓸 도구와 함께 [ADR-0012](adr/0012-vercel-web-analytics.md)에 있다. 1차를 배포한 뒤 더한 요청이다(2026-10-24).

## 비기능 요구사항

- **성능** - 콘텐츠는 사전 렌더링한 정적 셸로 보내고, 동적인 부분만 따로 스트리밍합니다.
- **접근성** - 키보드로 모든 기능을 쓸 수 있고, 색 대비를 지키고, `prefers-reduced-motion`을 따릅니다.
- **비용** - 질문 창은 하루 예산을 넘으면 스스로 꺼집니다.
- **개인정보** - 질문 창의 질문을 저장할지와 보관 기간은 F7 착수 때 정합니다. 저장한다면 개인정보처리방침 페이지를 함께 만듭니다. 방문 통계는 쿠키 없이 익명으로 세므로 사이트에 따로 알리지 않습니다(2026-10-24).
