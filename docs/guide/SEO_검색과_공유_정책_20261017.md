# 검색과 공유 정책

> 정함: 2026-10-17 (사이트 주소 점검 todo의 5번, 질문 라운드)
> 코드: `src/lib/site-meta.ts`, `src/app/robots.ts`, `src/app/sitemap.ts`, `src/components/home/profile-json-ld.tsx`, `scripts/og-image.mjs`, `next.config.ts`(`outputFileTracingIncludes`)
> 확인: `e2e/seo.spec.ts`

이 사이트가 검색엔진과 AI 답변에 어떻게 보이고, 링크를 보냈을 때 어떻게 보이는지에 대한 정책입니다. 구현하며 겪은 문제와 해결도 함께 둡니다. 다음에 페이지를 더하거나 다른 프로젝트에서 같은 것을 만들 때 같은 실수를 반복하지 않기 위해서입니다.

## 바탕

- 네 페이지(`/`, `/work`, `/ai`, `/resume`)는 빌드 때 HTML로 만들어져 글이 그대로 읽힙니다. 검색과 AI 답변에 필요한 바탕은 처음부터 있었습니다.
- 2026-10-17 점검 때는 `og:*` 태그가 없어서, 메신저나 메일로 링크를 보내면 제목과 그림 없이 주소만 보였습니다.
- Google은 AI 개요와 AI 모드에 나오기 위해 따로 할 일이 없다고 밝힙니다. 색인되어 검색 결과에 스니펫으로 나올 수 있으면 됩니다([Google](https://developers.google.com/search/docs/appearance/ai-features)). 그래서 GEO(AI 답변 노출)도 SEO 기본기에서 시작합니다.

묻지 않고 넣은 기본 설정도 있습니다.

- 사이트 기준 주소(`metadataBase`)는 `https://jakeso.dev`입니다(ADR-0011). 미리보기 배포나 로컬에서 열어도 대표 주소와 공유 주소는 운영 주소를 가리킵니다.
- 페이지마다 대표 주소(canonical)를 둡니다.
- X(트위터)는 큰 그림 카드(`summary_large_image`)입니다.
- 사이트맵에 수정 시각은 넣지 않습니다. 빌드 시각밖에 알 수 없어 정확하지 않기 때문입니다.

## 페이지를 더할 때

1. 메타데이터는 `pageMetadata({ title, description, path })`로 만듭니다. `openGraph`를 페이지에서 직접 쓰지 않습니다.
   - Next의 메타데이터는 얕게 합쳐져서, 페이지가 `openGraph`를 정하면 부모의 `openGraph`가 통째로 바뀝니다.
   - 처음에 그림을 파일 규칙(`app/opengraph-image.png`)으로 두었더니, 하위 페이지의 `openGraph`가 덮어 그림이 홈에만 붙었습니다. 그래서 그림도 도우미가 매번 넣습니다.
2. `src/app/sitemap.ts`의 경로 목록과 `e2e/seo.spec.ts`의 `PAGES`에 더합니다.
3. 검색에 노출하지 않을 페이지라면 robots.txt와 페이지의 `robots` 메타데이터를 그때 같이 정합니다. 지금은 그런 페이지가 없습니다.
4. 배포 뒤 봇 User-Agent로 새 페이지가 200인지 보고, 카카오 공유 디버거에서 제목, 설명, 그림이 나오는지 봅니다. 브라우저로 열어 보는 것만으로는 아래 "봇에게만 홈과 `/ai`가 500"을 잡지 못합니다.

## 미리보기 그림을 다시 만들 때

- 첫 줄, 이름, 아바타, 색이 바뀌면 다시 만듭니다.
- 개발 서버(`npm run dev`)를 띄운 뒤 `npm run og:image`를 돌리고, 바뀐 `src/assets/og-image.png`를 커밋합니다.
  - 스크립트는 홈을 연 뒤 본문만 그림 카드로 바꿔 찍습니다. 그래서 사이트의 글꼴, 색, 첫 줄 모양을 그대로 씁니다.
  - 그림은 라이트 모드로 찍습니다. 메신저는 보는 사람의 다크 모드와 관계없이 같은 그림을 보여 줍니다.
- 그림은 가져온 파일(import)이라 주소에 내용 해시가 붙습니다. 그림이 바뀌면 주소도 바뀌어, 메신저가 이전 그림을 붙잡고 있지 않습니다.

## 대표 주소를 옮길 때

2026-10-19에 대표 주소를 `jakeso.dev`로 옮기며 따른 순서입니다(ADR-0011).

1. ADR을 먼저 고칩니다.
2. 새 도메인을 Vercel 프로젝트에 더합니다. 루트는 Production에 연결하고, `www`는 루트로 308시킵니다. 이전 주소는 아직 그대로 둡니다.
3. 코드의 주소를 바꾸고 PR로 배포합니다.
   - `src/lib/site-meta.ts`의 `SITE_URL`: canonical, og:url, 사이트맵, robots, JSON-LD가 모두 이 값을 씁니다.
   - `scripts/og-image.mjs`의 그림 속 주소: `npm run og:image`로 그림을 다시 만듭니다.
   - `e2e/seo.spec.ts`의 `SITE`.
4. 배포한 뒤에 이전 주소와 그 `www`를 새 주소로 308시킵니다.
   - `www`도 이전 루트를 거치지 않고 새 주소로 바로 보냅니다.
   - 3번보다 먼저 하면, 배포 전까지 공유 정보가 넘어가는 주소를 가리킵니다.
5. 하위 경로까지 붙여 확인합니다.
   ```bash
   curl -sI https://jakeso.dev/work        # 200
   curl -sI https://www.jakeso.dev/work    # 308, location: https://jakeso.dev/work
   curl -sI <이전 주소>/work               # 308, location: https://jakeso.dev/work
   ```
6. 검색엔진 등록과 이력서 원문의 주소도 새 주소로 합니다. 원문은 원본 저장소에서 고친 뒤 `npm run sync`로 가져옵니다.

## 겪은 문제와 해결

### Vercel에서 `www`를 더하자 루트가 `www`로 넘어감 (2026-10-19)

- **증상**: 프로젝트 Domains의 "Add Existing" 대화상자에 `www.jakeso.dev`를 쓰고 Enter를 눌렀더니 대화상자가 바로 제출됐습니다. `www.jakeso.dev`가 Production에 붙었고, Production이던 `jakeso.dev`는 `www.jakeso.dev`로 308되게 바뀌었습니다.
- **원인**
  - 이 대화상자는 Enter로 제출됩니다. 연결 방식의 기본값이 "Connect to an environment"(Production)라서, 고르기 전에 제출되면 그대로 붙습니다.
  - 루트와 `www`가 함께 Production에 붙자 Vercel이 루트를 `www`로 넘기게 바꿨습니다.
- **고친 것**
  - 먼저 `jakeso.dev`의 Edit에서 "Connect to an environment"(Production)로 되돌려 저장했습니다.
  - 그다음 `www.jakeso.dev`의 Edit에서 "Redirect to Another Domain", 308, `jakeso.dev`를 골라 저장했습니다.
  - 루트를 먼저 되돌린 것은 두 주소가 서로를 가리키지 않게 하려는 것입니다.
- **같은 실수를 막으려면**
  - 도메인을 쓴 뒤 Enter를 누르지 않습니다. 연결 방식(Redirect, 308, 대상 주소)을 먼저 고르고 Add를 누릅니다.
  - 저장한 뒤 목록에서 주소마다 상태(Production 또는 308 대상)를 읽고, 위 5번의 `curl -sI`로 확인합니다.

### 봇에게만 홈과 `/ai`가 500 (2026-10-17, PR #23)

- **증상**: 카카오톡에 홈 링크를 보내면 미리보기가 뜨려다 사라졌습니다. 브라우저로 열면 정상이었고, 로컬 검사도 모두 통과했습니다.
- **원인**
  - Next는 미리보기·검색 봇(`htmlLimitedBots`: 카카오, 페이스북, 슬랙, X, 빙, 네이버 등)에게 미리 만든 페이지 대신 요청마다 서버에서 새로 그립니다. 이때 운영 응답 헤더는 `x-vercel-cache: BYPASS`입니다. 구글봇과 일반 브라우저는 미리 만든 페이지를 받습니다.
  - 홈과 `/ai`는 그릴 때 CI 검사 수를 세려고 `.github/workflows/ci.yml`을 읽습니다(`src/lib/repo-stats.mjs`).
  - 빌드의 파일 추적이 `docs/adr/`는 서버 출력에 넣었지만 이 파일은 넣지 않았습니다. 그래서 Vercel에서만 `ENOENT`가 났습니다. 로컬 `next start`에는 저장소 전체가 있어 재현되지 않습니다.
- **고친 것**: `next.config.ts`의 `outputFileTracingIncludes`에 이 파일을 넣었습니다.
- **같은 실수를 막으려면**
  - 페이지를 그릴 때 `content/` 밖의 저장소 파일을 새로 읽게 되면, 빌드 뒤 `.next/server/app/**/page.js.nft.json`에 그 파일이 있는지 봅니다. 없으면 `outputFileTracingIncludes`에 더합니다.
  - 배포 뒤에는 봇 User-Agent로 받아 봅니다.
    ```bash
    curl -s -o /dev/null -w '%{http_code}\n' -A 'facebookexternalhit/1.1;kakaotalk-scrap/1.0' https://jakeso.dev/
    ```
  - 미리보기 배포는 Vercel 로그인 보호가 걸려 있어 그냥 받으면 로그인 화면으로 넘어갑니다. `vercel curl`로 봅니다.
    ```bash
    vercel curl / --deployment <미리보기 주소> -- --silent --output /dev/null --write-out '%{http_code}\n' --user-agent 'facebookexternalhit/1.1;kakaotalk-scrap/1.0'
    ```
  - 500이면 `vercel logs --environment production --level error --expand`로 오류 내용을 봅니다.

### 카카오톡 미리보기를 확인하는 방법

- 카카오 디벨로퍼스의 [카카오톡 URL 메타 정보 관리](https://developers.kakao.com/tool/debugger/sharing)에서 주소를 조회하면 카카오가 가져간 제목, 설명, 그림이 보입니다. 카카오 로그인이 필요합니다.
- 실패하면 "유효하지 않은 URL"만 나오고 이유는 보이지 않습니다. 이때는 카카오 스크래퍼의 User-Agent(`facebookexternalhit/1.1;kakaotalk-scrap/1.0`)로 직접 받아 응답 코드를 봅니다. 이번 500도 이 방법으로 찾았습니다.
- 카카오는 주소별로 결과를 저장해 두고 다시 씁니다. 고친 뒤에도 예전 결과가 보이면 같은 화면의 "캐시 초기화"를 누릅니다. `https`와 `http`, 끝 슬래시가 있는 주소와 없는 주소가 따로 저장되므로 각각 지웁니다.
- 이미 보낸 메시지의 카드는 바뀌지 않습니다. 새로 보내서 확인합니다.

### 미리보기 그림이 홈에만 붙음 (2026-10-17, PR #22)

- 그림을 파일 규칙(`app/opengraph-image.png`)으로 두었더니 하위 페이지 세 곳에는 그림 태그가 없었습니다.
- 원인과 해결은 위 "페이지를 더할 때" 1번에 있습니다. 빌드 결과 HTML을 페이지마다 열어 봐서 찾았습니다.

### 미리보기 그림의 아바타가 흐릿함 (2026-10-17, PR #22)

- 머리의 아바타 그림을 그대로 크게 쓰면 흐릿했습니다. next/image가 머리 크기(28px)에 맞춰 줄인 그림이기 때문입니다.
- 그래서 `scripts/og-image.mjs`는 next/image 주소의 `url` 값에서 원본 그림 주소를 꺼내 씁니다.

## 기준선

2026-10-17, 이 변경을 배포하기 전에 쟀습니다.

- 질문 세 개를 문구 그대로 물었습니다.
