다른 곳에서 만든 문서(PDF 같은 결과물)를 사이트 페이지로 옮길 때의 기준입니다. 사례가 늘거나 다른 사이트에서 같은 일을 할 때 따릅니다. 옮기며 겪은 문제도 함께 둡니다.

## 정한 것

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 원본 | PDF가 아니라 PDF를 만드는 파일을 동기화합니다. 본문(txt), 제목과 칸 설명과 자를 자리(json), 그림(png) 세 개입니다 | PDF에서 글자를 뽑으면 줄과 순서가 깨지고, 그림은 PDF 안에서 다시 잘라야 합니다. 본문을 고친 뒤 PDF를 다시 만들어야 사이트에 반영되는 단계도 없어집니다 |
| 문장 | 원본 문장을 고치지 않고 그대로 그립니다. 테스트의 기대값도 원본 파일에서 읽습니다 | 원본과 사이트가 어긋나지 않게 하기 위해서입니다. 원본 문장이 바뀌어도 코드와 테스트는 그대로입니다 |
| 그림 동기화 | 바이트 그대로 옮깁니다. 그림에는 변환 규칙을 달 수 없고, 가져올 때 눈으로 확인합니다. `npm run sync -- --check`는 그림을 바이트로 비교합니다 | 민감정보 검사는 글자만 읽습니다 |
| 사이트에만 맞는 처리 | 작성자 이름을 빼는 일은 동기화 규칙(`replace-line`)으로, 칸 자르기는 사이트 코드로 합니다 | 원본은 다른 문서에도 쓰므로 고치지 않습니다 |
| 입구 버튼 이름 | 사이트의 다른 상세 링크와 같은 "자세히 보기"를 씁니다 | 처음 정한 "한눈에 보기"는 요약을 본다는 뜻이라, 4컷과 긴 본문이 있는 페이지와 맞지 않았습니다. 요약은 입구 띠의 작은 그림이 이미 보여 줍니다 |
| 자리 | 긴 사례는 목록 페이지 안에 펼치지 않고 서브페이지로 두고, 목록 페이지 맨 위에 입구 띠를 둡니다. 헤더 메뉴는 사례가 두세 개가 될 때까지 늘리지 않습니다 | 목록 페이지가 한참 길어지고, 글이 하나뿐인 메뉴는 비어 보입니다. 팝업은 주소가 없어 링크로 보낼 수 없어서 쓰지 않습니다 |
| 칸 자르기 | 그림 한 장을 칸 비율의 상자 안에 % 위치로 놓아 그 칸만 보이게 합니다. 칸마다 파일을 만들지 않습니다 | 네 칸이 같은 그림 주소를 써서 요청이 한 번입니다. 원본 그림이 바뀌어도 json의 자를 자리만 따라갑니다 |
| 대체 텍스트 | 칸 그림은 비우고 설명을 `figcaption`으로 묶습니다. 입구의 작은 그림도 비우고, 링크 이름은 `aria-label`("AI 도구 활용 사례 자세히 보기")로 줍니다 | 칸의 뜻은 바로 아래 설명이 그대로 말합니다. 같은 말을 두 번 읽히지 않게 합니다 |
| 메뉴 표시 | 메뉴 아래의 페이지에서도 그 메뉴에 밑줄을 붙이고, 화면 읽기 프로그램에는 `aria-current="true"`로 알립니다 | 메뉴 안에 있다는 것은 보여 주되, 지금 페이지 자체는 아니라고 구분합니다 |
| 다크 모드 | 그림은 밝기를 낮추거나 상자에 넣지 않고 그대로 둡니다 | 서비스 캡처, 영상 썸네일처럼 그림 안의 색으로 봅니다 |

## 만드는 방법

- **칸 자르기**: 칸의 자리 (x, y, 폭 w, 높이 h)를 안쪽으로 8px씩 줄인 뒤, 아래처럼 계산합니다(`panelBox()`).
  - 상자: `aspect-ratio: w / h`
  - 그림 크기: 폭은 `원본 폭 / w × 100%`, 높이는 `원본 높이 / h × 100%`
  - 그림 위치: `left: -x / w × 100%`, `top: -y / h × 100%`
  - `next/image`의 `sizes`는 칸이 아니라 그림 전체의 폭입니다(칸 폭 × 원본 폭 / w).
- **형식 검사**: 칸이 넷이 아니거나, 자리가 그림 밖으로 나가거나, 부제에 작성자 이름(`|`)이 남아 있으면 빌드가 멈춥니다. `scripts/lib/ai-case.test.mjs`는 동기화한 그림의 크기(PNG 머리)를 읽어 네 칸이 그림 안에 있는지 봅니다.
- **봇에게도 열리는지**: 글은 `content.ts`에서 경로를 고정 문자열로 읽습니다. 빌드 뒤 `.next/server/app/ai/case/page.js.nft.json`에 `content/synced/ai-case.json`과 `.txt`가 있는지 보고, `next start`에 카카오 봇 User-Agent로 요청해 200인지 봅니다([검색과 공유 가이드](SEO_검색과_공유_정책_20261017.md)의 "봇에게만 500").

## 겪은 문제와 주의할 점

### 다크 모드에서 칸에 흰 테두리가 보임 (2026-10-20, 시안)

- **증상**: 시안을 다크 모드로 찍자 칸마다 흰 테두리가 보였습니다. 라이트 모드에서는 바탕과 같은 색이라 보이지 않았습니다.
- **원인**: 원본 그림의 칸에는 1px 흰 여백이 있고, 모서리가 둥글어 바깥쪽이 흽니다. 왼쪽 위 모서리에서 대각선으로 7px까지 흰 화소였습니다. json의 자를 자리는 이 여백까지 포함합니다.
- **고친 것**: 자를 자리보다 안쪽으로 8px 더 자릅니다(`PANEL_INSET`). 원본 json은 고치지 않습니다.
- **막는 방법**: 그림을 잘라 쓸 때는 시안 단계부터 다크 모드 캡처를 함께 봅니다. 가장자리 화소를 대각선으로 읽어 여백 폭을 재고 줄일 양을 정합니다.

### 원본 그림이 작음

- 원본은 1024×1024 한 장이라, 잘라 낸 칸 하나가 약 454px입니다. 데스크톱 2×2는 칸을 약 25rem으로 보여 주므로 레티나 화면에서는 살짝 흐립니다.
- 그림을 크게 다시 만들면 AI가 새로 그려 원본 PDF의 그림과 달라질 수 있습니다. 그래서 그대로 쓰고, 거슬리면 원본 저장소에서 다시 만듭니다.

### 개수를 세는 기준이 달라 숫자가 맞지 않아 보임 (2026-10-20, 기획)

- 본문의 가이드 문서 수(71개)를 확인하려고 폴더의 md를 세었더니 72개였습니다. 한쪽 폴더의 색인 파일(INDEX.md)까지 셌기 때문입니다. 다른 쪽은 README.md를 빼고 세어 기준이 섞였습니다.
- 본문의 숫자는 두 폴더 모두 색인 파일을 뺀 같은 기준이라 맞았습니다. 개수를 대조할 때는 무엇을 빼고 세는지부터 원본과 맞춥니다.

## 영상에서 페이지 만들기 (Jake English, 2026-11-11)

공개한 소개 영상을 사이트 페이지로 옮길 때의 기준입니다. 위 내용은 PDF를 옮기는 기준이고, 이 절은 영상에서 그림과 글을 가져오는 기준입니다. 영상이 아닌 다른 결과물(발표 자료 같은 것)을 페이지로 옮길 때도 같은 순서로 봅니다.

### 정한 것

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 그림의 출처 | 공개한 영상에서만 가져옵니다. 이야기 4컷만 Gemini 앱으로 그렸습니다 | 공개하지 않은 화면이 사이트에 섞이지 않게 하고, 영상과 페이지가 같은 모습이 되게 합니다 |
| 다시 그리는 것 | 단계 이름, 그림 안의 제목, 말풍선은 HTML로 다시 그려 찍습니다. 앱 화면은 시연 영상에서 폰 화면만 잘라 씁니다 | 영상 프레임에 박힌 자막과 설명을 쓰면 페이지 글과 겹치고, 합니다체로 맞출 수 없습니다 |
| 슬라이드 글자 | 페이지 문단과 뜻이 다른 글자는 찍을 때만 바꿉니다. 원본 파일은 고치지 않습니다 | 영상은 그대로 두고, 사이트의 문단과 그림이 서로 다른 말을 하지 않게 하기 위해서입니다 |
| 그림 안의 제목 줄 | 잘라 냅니다 | 장 소제목과 같은 말이 그림에도 있으면 두 번 읽힙니다 |
| 4컷 파일 | 칸마다 파일 하나로 둡니다 | 나중에 그림 하나만 바꿀 수 있습니다. 이야기 4컷은 칸마다 따로 그린 그림이라 처음부터 네 파일이었습니다 |
| 번호 | 칸이 한 순서로 이어지는 이야기 4컷에만 번호를 붙입니다. 연습 종류가 다른 앱 화면 4컷(연습하는 방법)에는 붙이지 않고, 그림 안의 연습 종류 이름으로 구별합니다. 4컷을 처음 정할 때 앱 코드의 연습 종류와 누가 먼저 말하는지를 확인합니다 | 번호를 붙인 네 칸은 정해진 한 순서로 읽힙니다. 처음에 번호 1~4로 두었더니 라이언이 늘 먼저 묻는 흐름처럼 읽혔고, 앱 코드를 보니 연습은 세 가지이고 누가 먼저 말할지는 상황에 따라 달랐습니다(2026-11-11) |
| 재생기 | 넣지 않고 썸네일을 누르면 유튜브로 보냅니다 | 페이지가 가볍고, 유튜브 링크 클릭은 방문 통계의 `outbound`로 잡힙니다 |
| 숫자 | 센 방법과 날짜 범위를 함께 고정한 값으로 씁니다. 일부에만 해당하는 문장은 숫자를 넣어 씁니다 | 저장소가 자라도 값이 바뀌지 않습니다. "리뷰 에이전트가 먼저 검토했고"라고만 쓰면 78개 모두로 읽혀, "78개 가운데 58개"로 씁니다 |
| 대체 텍스트 | 그림은 모두 비웁니다 | 썸네일은 링크 글이, 4컷은 설명이, 슬라이드는 바로 아래 문단이 같은 내용을 말합니다 |

### 만드는 방법

원본은 소개 영상을 만든 작업 폴더(이 저장소 밖)에 있습니다. 그 폴더에서 파일을 읽기만 하고, CI에서는 돌릴 수 없어 그림은 커밋하고 만든 방법은 여기에 둡니다. 그림은 `src/assets/ai/jake-english/`에 있고, `src/lib/jake-english-images.ts`가 가져다 씁니다.

| 파일 | 크기 | 만드는 법 |
|---|---|---|
| `video.jpg` | 1920×1080 | 영상 썸네일 원본(PNG)을 `ffmpeg -i <썸네일> -q:v 3 video.jpg` |
| `flow-1.jpg`~`flow-4.jpg` | 1280×720 | 시연 영상의 폰 화면을 잘라 단계, 제목, 말풍선을 HTML로 다시 그려 찍은 4컷 칸. 칸 순서는 첫 화면, 대화 연습하기(상황 정하기), 대화 연습하기(본보기를 듣고 말하기), 자유 대화입니다(2026-11-11에 바꿈). 만드는 법은 표 아래 첫 항목에 있습니다 |
| `story-1.jpg`~`story-4.jpg` | 1200×1200 | Gemini 앱으로 칸마다 그린 정사각 그림을 1200×1200으로 줄입니다. 띠의 작은 그림도 이 파일을 씁니다 |
| `slide-1.jpg`~`slide-4.jpg` | 1560×690 | 슬라이드 원본(HTML)을 1920×1080으로 다시 찍고, 제목 줄을 뺀 `crop=1560:690:40:230`을 네 장 모두 같은 자리에서 잘라 JPG로 저장합니다 |

- 앱 화면 4컷(`flow-*.jpg`)은 이렇게 만들었습니다. 앱 시연 영상(1920×1080)에서 칸마다 고른 초의 프레임을 ffmpeg로 뽑고, 폰 화면을 (245, 35)에서 462×1012로 자릅니다. 칸은 1920×1080 HTML 한 쪽입니다. 배경은 #14161c, 폰은 왼쪽(x 245~707, y 35~1047)에 놓습니다. 단계 표시(#9679ff, 40px), 제목(#fed62c, 76px, 굵기 800), 말풍선 상자(#242830, 모서리 22px)를 두고, 상자 안에 화자 이름(라이언 등은 #68abff, 소희는 #5fd08a, 34px)과 대사(48px)를 씁니다. 글은 모두 `word-break: keep-all`입니다. 이 쪽을 Playwright로 1920×1080에 찍어 너비 1280의 JPG로 저장합니다. HTML 틀은 이 저장소에 두지 않았습니다.
- 1장 슬라이드는 찍을 때만 세 줄을 문단에 맞춰 바꿉니다. 이름표와 글은 "첫마디: 외국인이 길을 물었을 때 알아들었는데 첫마디가 나오지 않았다", "AI 튜터: AI 활용이 일상이 되면서 AI 튜터도 많이 생겼다 / 써 봤지만 입맛에 맞지 않았다", "그래서: 어떤 상황이든 직접 정해 연습하고, / 내 입맛에 맞게 반응하는 앱 / 내가 직접 만들었다"(강조 상자)입니다. 말투는 슬라이드의 짧은 메모체로 둡니다. 이름표가 길어져 줄이 깨지면 그 장면에서만 이름표 칸 너비를 맞추는데, "AI 튜터"는 지금 너비에 한 줄로 들어갔습니다. 첫마디와 AI 튜터 상자의 글은 두 줄, 그래서 상자의 글은 세 줄입니다. 세 상자가 칸 높이를 똑같이 나눠 가져 세 줄도 들어갑니다. 세 상자가 폰보다 짧아 그림 왼쪽 아래가 비어 보여서, 이 장면에서만 상자 칸의 높이를 폰 아래 끝까지 늘리고 세 상자가 그 높이를 나눠 갖게 했습니다(상자 사이 1.75rem). 자르는 자리와 크기는 다른 장과 같습니다. 슬라이드를 잘라 쓸 때는 잘린 판 안에서 왼쪽과 오른쪽의 아래 끝이 맞는지 봅니다. 3장 슬라이드는 두 상자 제목을 "Claude Code로 한 것", "제가 정한 것"으로 바꾸고 아래 줄을 뺍니다.
- 5장은 슬라이드 대신 큰 숫자입니다. 슬라이드 5/5는 오른쪽 인물 자리가 비어 있어 쓰지 않습니다.
- 숫자를 다시 세려면 jake-english 저장소에서 `gh pr list --state merged`로 기간(2026-11-04부터 11-09까지, 한국 시각)의 머지 PR을 세고, 리뷰 코멘트가 달린 PR 수도 같은 기간 안에서 셉니다.
- 새 그림을 더하면 가장자리에 흰 화소가 없는지 봅니다. 이번에는 sharp로 칸 그림마다 네 모서리 화소를 읽었고(앱 화면 4컷의 모서리는 모두 칸 배경색 #14161c이고 흰색이 없었습니다), 이어서 다크 모드 캡처를 눈으로 확인했습니다. `npm run check:units`는 손으로 쓴 px 길이만 검사하므로 그림 가장자리는 잡지 못합니다.

### 겪은 문제와 주의할 점

#### 두 띠의 작은 그림 줄이 7px 어긋남 (2026-11-11, 구현)

- **증상**: `/ai` E2E의 두 입구 그림 줄 높이 비교가 폭 1024와 1280에서 7px 차이로 실패했습니다.
- **원인**: 테스트가 두 띠의 첫 `img`의 위치를 비교했습니다. 사례 띠는 큰 그림 한 장을 칸마다 잘라 쓰는 구조라 `img`가 자른 칸보다 위에서 시작합니다.
- **고친 것**: 각 띠의 그림 줄(링크의 마지막 자식 요소)의 위치를 비교합니다(커밋 07775e6).
- **막는 방법**: 칸 안에서 더 큰 그림을 잘라 보여 주는 구조는 `img`가 아니라 칸이나 줄을 재서 비교합니다.
