# 모바일 표

> 정함: 2026-10-17 (모바일 `/resume`에서 연락처와 학력 표가 옆으로 넘어가 시안을 비교해 정함)
> 코드: `src/lib/markdown-plugins.mjs`(`rehypeStackTables`), `src/components/markdown.tsx`(`stackTables`), `src/app/globals.css`(`.md-stack`)
> 확인: `scripts/lib/markdown-plugins.test.mjs`의 `rehypeStackTables`, `e2e/resume.spec.ts`의 "연락처와 학력 표"
> 캡처: [design/resume-tables](../design/resume-tables/)

좁은 화면에서 넘치는 표를 어떻게 보여 줄지에 대한 기준입니다. 다른 사이트를 만들 때도 같은 방식으로 씁니다. 구현하며 겪은 문제와 주의할 점도 함께 둡니다.

## 정한 것

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 방식 | 좁은 화면(640px 미만)에서 넘치는 표는 옆으로 넘기지 않고, 행마다 상자 하나로 그림 | 표를 옆으로 넘기면 칸이 화면 밖에 숨어, 넘겨야 한다는 것을 알아차리기 어렵습니다 |
| 칸 | 왼쪽에 열 머리글 이름표, 오른쪽에 값(격자 `4.5rem 1fr`) | 위아래로 쌓는 안보다 짧고, 이름표와 값이 한눈에 짝지어집니다 |
| 대상 | 네 칸 이상이거나 본문 행이 하나뿐인 표 | 여러 행에 세 칸 이하인 표(수상: 연도, 수상명, 수여기관)는 칸 안에서 줄을 바꿔 화면에 들어가고, 표로 두어야 훑어보기 쉽습니다 |
| 굵기 | 행이 여럿인 표는 첫 칸을 굵게 해 상자 제목처럼, 행이 하나뿐인 표(연락처)는 모두 보통 굵기 | 연락처에서 이메일만 굵으면 어색했습니다 |
| 넓은 화면과 인쇄 | 표 그대로 | 넓은 화면은 표가 들어가고, 인쇄는 용지 폭에 맞춘 표가 읽기 좋습니다 |

## 만드는 방법

- **고르기**: 마크다운을 HTML로 바꾸는 단계(rehype 플러그인)에서 표마다 머리글 칸 수와 본문 행 수를 셉니다. 대상 표에 클래스(`md-stack`)를 붙입니다.
- **이름표와 값**: 대상 표의 칸마다 맨 앞에 `<span class="md-label" aria-hidden="true">열 머리글</span>`을 넣고, 칸의 원래 내용은 `<span class="md-value">`로 감쌉니다. 이름표는 좁은 화면에서만 보이게 CSS로 정합니다.
- **역할**: 대상 표의 요소에 `role`(`table`, `rowgroup`, `row`, `columnheader`, `cell`)을 적습니다.
- **CSS** (`@media screen and (width < 40rem)`)
  - `table`, `tbody`, `tr`, `td`를 블록으로 바꾸고, `thead`는 화면에서만 숨깁니다(`sr-only`).
  - `tr`은 선 상자, `td`는 `grid-template-columns: 4.5rem 1fr` 격자입니다.
  - `screen` 조건이라 인쇄에는 적용되지 않습니다.
- **표를 감싼 상자**: 넓은 표를 옆으로 넘기려고 표를 상자(`div.md-table`, `overflow-x: auto`)로 감쌌다면, 플러그인이 붙인 클래스를 그 상자로 옮깁니다. 좁은 화면에서는 상자의 테두리와 넘김을 없앱니다.

## 겪은 문제와 주의할 점

### 덮어쓴 규칙이 적용되지 않음 (겪음)

- 기존 규칙 `.md-resume table:has(th:nth-child(4)) { min-width: 32.5rem }`이 새 규칙 `.md-resume .md-stack :is(table, …) { min-width: 0 }`을 이겼습니다. 그래서 학력 표가 계속 520px로 넘쳤습니다.
- `:has()`의 구체성은 괄호 안 선택자만큼 더해집니다. 그래서 `(0,2,2)`가 되어, 생각보다 구체적이었습니다.
- 같은 이유로 `display: block`을 준 규칙이 뒤에 쓴 칸의 `display: grid`를 이겨, 이름표가 값 위로 올라갔습니다.
- 새 규칙에 `.md-table.md-stack`까지 써서 구체성을 올렸습니다. 같은 요소의 `display`를 두 번 정할 때는 구체성을 맞추고 순서로 이기게 합니다.
- 확인은 화면 캡처와 함께 `getComputedStyle`로 실제 값(`min-width`, `display`)을 봅니다.

### 섞인 칸이 이름표 칸으로 떨어짐 (리뷰에서 찾음)

- 처음에는 이름표만 칸 앞에 붙이고 원래 내용은 그대로 두었습니다. 칸(`td`)이 격자라서, 글자와 굵은 글자, 링크가 섞인 칸(`앞 **굵게** 뒤`)은 조각마다 격자 항목이 됩니다. 그러면 굵은 글자가 다음 줄의 이름표 칸으로 떨어집니다.
- 이 사이트의 연락처와 학력 칸은 글자나 링크 하나라 화면에는 드러나지 않았지만, 원본 이력서가 바뀌면 생길 수 있었습니다. PR 리뷰에서 찾았습니다.
- 원래 내용을 값 하나(`.md-value`)로 감싸, 격자 항목이 늘 이름표와 값 둘이 되게 했습니다. 단위 테스트가 섞인 칸을 확인합니다.

### 이름표를 CSS `::before`로 그리면 두 번 읽힘 (주의)

- `td::before { content: attr(data-label) }`로 그리면 간단하지만, 생성 글자는 화면 읽기 프로그램이 읽습니다. 표 탐색에서 열 머리글을 읽고 이름표를 또 읽게 됩니다.
- 그래서 이름표를 `aria-hidden="true"`인 실제 글자로 넣고, 넓은 화면에서는 `display: none`으로 숨깁니다. E2E는 칸의 접근성 이름에 이름표가 섞이지 않는지 봅니다(`getByRole("cell", { name: /^\S+@\S+$/ })`).

### `display`를 바꾸면 표 구조가 사라질 수 있음 (주의)

- 브라우저에 따라 `table`, `tr`, `td`의 `display`를 바꾸면 접근성 트리에서 표 구조를 지웁니다.
- 대상 표에 `role`을 적어 둡니다. E2E는 `getByRole("table")`의 개수로 표가 남아 있는지 봅니다.

### 어느 표를 바꿀지 CSS로 고르기 어려움 (주의)

- "본문 행이 하나뿐인 표를 감싼 상자"처럼 고르려면 `:has()` 안에 `:has()`가 필요한데, CSS는 이를 허용하지 않습니다.
- 그래서 고르는 일은 플러그인(JS)이 하고, CSS는 클래스만 봅니다. 고르는 규칙은 단위 테스트로 확인합니다.

### 칸 안의 주소가 낱말 중간에서 갈라짐 (겪음, 2026-10-15)

- 전역 `overflow-wrap: anywhere`가 표 칸의 최소 폭을 줄여, 모바일에서 GitHub 주소가 중간에서 갈라졌습니다.
- 표 칸은 `overflow-wrap: normal`로 둡니다. 주소를 끊지 않으니 좁은 화면에서는 표가 넘치게 되고, 이것이 이 가이드의 상자 방식이 필요해진 이유입니다.

## 확인할 것

- 360, 375, 639에서 대상 표에 가로 넘김이 없고(`scrollWidth - clientWidth ≤ 0`), 페이지 전체에도 가로 스크롤이 없는지 봅니다.
- 640 이상과 인쇄(`emulateMedia({ media: "print" })`)에서 표 그대로인지 봅니다.
- 라이트와 다크 캡처를 함께 봅니다.
