# 모바일 메뉴

> 정함: 2026-10-17 (실기기 캡처를 보고 시안을 비교해 정함)
> 코드: `src/components/mobile-menu.tsx`, `src/components/nav-links.tsx`, `src/components/site-header.tsx`, `src/app/globals.css`(`--scrim`)
> 확인: `e2e/home.spec.ts`의 "모바일 메뉴"
> 캡처: [design/mobile-menu](../design/mobile-menu/)

모바일 헤더의 메뉴를 어떻게 보이고 어떻게 동작하게 하는지에 대한 기준입니다. 다른 사이트를 만들 때도 이 모양과 동작을 그대로 씁니다. 구현하며 겪은 문제와 주의할 점도 함께 둡니다.

## 정한 것

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 버튼 | 아이콘(☰), 열리면 X로 바뀜. 이름 "메뉴"는 화면 읽기용 글자로 둠. 누르는 크기 2.75rem, 아이콘 오른쪽 끝은 본문 여백 선에 맞춤 | 모바일에서 흔히 쓰는 표시라 읽지 않아도 알아봅니다. 처음의 "메뉴" 글자 버튼은 낯설었습니다 |
| 펼친 모양 | 헤더 바로 아래, 화면 폭 전체 패널. 뒤 페이지는 어둡게 덮음 | 버튼 아래 좁은 상자는 항목이 적으면 썰렁하고 오른쪽이 비어 보였습니다 |
| 줄 | 왼쪽에 이름, 오른쪽에 페이지 제목(브라우저 제목 앞부분). 높이 3.5rem, 줄 사이 옅은 선 | 영어 메뉴 이름(Work, AI, Resume)이 어떤 페이지인지 바로 보이고, 빈 공간을 쓸모 있는 정보로 채웁니다 |
| 담는 것 | 페이지 이동만. 연락처(이메일, GitHub)는 넣지 않음 | 메뉴의 성격이 섞이고, 연락처가 없는 데스크톱 헤더와 달라집니다 |
| 지금 보는 페이지 | 이름 글자에 600 굵기와 두께 2 밑줄, 링크에 `aria-current="page"` | 세로 목록이라 굵기가 바뀌어도 흔들리지 않습니다 |
| 닫힘 | 메뉴 링크, 메뉴 밖, 어둡게 덮은 곳을 누를 때, Esc(버튼에 초점을 돌려줌), 뒤로 가기 | 헤더가 루트 레이아웃이라 페이지를 옮겨도 남습니다. 열린 메뉴가 새 페이지를 가리지 않아야 합니다 |
| 바탕 구조 | `<details>`와 `<summary>` | 스크립트가 오기 전에도 열리고, 열림 상태를 화면 읽기 프로그램에 알려 줍니다 |

## 만드는 방법

- 헤더에 `relative`를 주고, `<details>`는 위치 기준을 두지 않습니다(`group`만). 패널(`nav`)은 `absolute inset-x-0 top-full`로 헤더 아래 화면 폭 전체에 붙습니다. 모바일에서는 헤더 폭이 곧 화면 폭입니다.
- `<summary>` 안에 `<span className="sr-only">메뉴</span>`와 SVG 두 개를 둡니다. ☰는 `group-open:hidden`, X는 `hidden group-open:block`이고 둘 다 `aria-hidden`입니다.
- 패널 뒤에 덮는 층(`aria-hidden` div, `absolute inset-x-0 top-full h-screen bg-scrim`)을 둡니다. 색은 토큰 `--scrim`으로 라이트 검정 20%, 다크 검정 60%입니다.
- 닫기: 문서의 `pointerdown`이 `<details>` 밖이면 닫고, Esc는 닫은 뒤 `<summary>`에 초점을 줍니다. 뒤로 가기(`popstate`)와 메뉴 링크의 `onClick`도 닫습니다. 덮는 층은 따로 `onClick`으로 닫습니다(아래 주의할 점).

## 겪은 문제와 주의할 점

### 다크에서 덮는 층이 보이지 않음 (겪음)

- 처음에는 라이트와 다크 모두 검정 20%로 덮었습니다. 다크 바탕(#0f1011)은 이미 어두워 덮인 것이 거의 보이지 않았습니다.
- 색 토큰 `--scrim`을 만들어 다크에서만 60%로 올렸습니다. 덮는 층이나 그림자처럼 바탕과의 차이로 보이는 것은 다크 캡처를 따로 찍어 확인합니다.

### 메뉴의 페이지 제목을 h1과 맞추려다 어긋남 (겪음)

- 줄의 페이지 제목이 그 페이지 제목과 같은지 E2E로 확인하려고 처음에는 h1과 비교했습니다. 이력서 페이지의 h1은 이력서 원문의 이름("소재희")이라 "이력서"와 달랐습니다.
- 브라우저 제목 앞부분("이력서 · 소재희"의 "이력서")과 비교하도록 바꿨습니다. 페이지 제목을 메뉴에 둘 때는 무엇과 맞출지(h1인지 브라우저 제목인지) 먼저 정합니다.

### 덮는 층은 "메뉴 밖 누름"으로 잡히지 않음 (주의)

- 덮는 층을 `<details>` 안에 두면 `details.contains(target)`가 참이라, 문서 단위의 바깥 누름 처리로는 닫히지 않습니다. 층에 직접 `onClick` 닫기를 붙입니다.
- 층을 `<details>` 밖에 두면 열림 상태를 따로 관리해야 해서, 안에 두는 편이 단순합니다.

### 밑줄이 줄 전체로 번짐 (주의)

- 한 링크 안에 이름과 페이지 제목을 같이 두므로, 지금 보는 페이지 표시를 링크에 주면 `text-decoration`이 안쪽 글자(페이지 제목)까지 번집니다. 안쪽에서 `no-underline`을 줘도 지워지지 않습니다.
- 표시는 이름 `<span>`에만 줍니다. E2E도 모바일에서는 링크가 아니라 이름 글자의 밑줄을 봅니다.

### E2E에서 덮인 요소 클릭이 막힘 (주의)

- 메뉴가 열려 있으면 덮는 층이 페이지 글을 가리므로, Playwright로 페이지 제목 같은 요소를 누르면 "다른 요소가 클릭을 가로챈다"며 기다리다 실패합니다.
- 바깥 누름은 `page.mouse.click(x, y)`로 헤더의 빈 곳과 덮은 곳을 각각 눌러 확인합니다.

## 확인할 것

- 375에서 라이트와 다크로 열고 닫은 모습을 찍어 봅니다.
- 키보드로 Tab → Enter(열림) → Esc(닫히고 버튼에 초점)를 해 봅니다.
- 메뉴 링크로 옮긴 뒤 메뉴가 닫히고 새 페이지 제목이 보이는지, 지금 보는 페이지 표시가 따라오는지 봅니다.
