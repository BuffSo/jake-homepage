# 원본 문서의 구성이 바뀌었을 때 사이트를 맞추는 기준

> 작성: 2026-11-23 · 분야: 콘텐츠 동기화(`content/synced/`), `/work`

원본(이력서, 포트폴리오)은 다른 저장소에 있고 인쇄본을 만드는 문서입니다. 사이트는 그 원문을 동기화해 문장을 다시 쓰지 않고 그립니다(ADR-0003). 2026-11-23에 포트폴리오 원본의 구성이 통째로 바뀌었고, 그때 정한 기준과 겪은 문제를 적습니다.

## 정한 기준

1. **원본은 사이트 때문에 고치지 않습니다.** 원본은 검토가 끝난 인쇄용 문서입니다. 사이트에서만 달라야 하는 것은 사이트 쪽 규칙으로 둡니다.
2. **사이트는 인쇄본보다 자세해도 됩니다.** 원본이 분량 때문에 뺀 내용은 동기화 규칙(`scripts/sync.config.mjs`의 `insert-before`, `append-section`)으로 사이트에만 남깁니다.
   - 글은 지우기 전의 원문 그대로 옮깁니다. 줄 단위로 고르고, 문장을 잘라 붙이지 않습니다.
   - 새 원문의 문장이나 그림이 같은 말을 하면 남기지 않습니다. 같은 말이 두 번 나오면 어느 쪽이 지금 사실인지 흐려집니다.
   - 규칙마다 `reason`에 언제, 왜 남기는지 씁니다. 무엇을 공개하는지가 설정 파일의 diff로 보입니다.
   - 남긴 블록 목록은 IA 문서에 표로 둡니다.
3. **규칙은 원본이 다시 바뀌면 멈춰야 합니다.** `insert-before`는 끼울 자리의 줄이 정확히 한 줄이어야 하고, 블록의 첫 줄이 원본에 이미 있으면 멈춥니다. 조용히 엉뚱한 곳에 끼우거나 두 번 싣지 않습니다.
4. **원문을 읽는 코드는 형식이 다르면 멈춥니다.** `/work`는 원문의 절 제목, 기간·역할·주소 줄, 스택 줄, 인용 한 줄, 한눈에 보기 표를 읽습니다(`src/lib/portfolio.mjs`). 못 읽으면 빌드와 시험이 멈춥니다. 반쯤 맞게 그리는 것보다 낫습니다.
5. **원문의 인쇄용 장치는 버리고 모양은 사이트 CSS로 줍니다.** `style` 속성과 `<style>` 요소를 버립니다(`rehypeDropStyle`). 그림 폭, 가운데 정렬 같은 모양은 `globals.css`의 `.md` 아래에 다시 씁니다.
6. **사이트 전용 글의 근거 줄(`sources`)은 원문과 대조합니다.** 원문에 같은 문장이 없어지면 시험이 실패합니다. 화면 글은 그대로 두고 근거 줄을 새 원문의 같은 뜻 문장으로 바꿉니다. 근거가 있던 절이 통째로 없어졌고 본인 작업의 사실이면, 본인 확인을 받아 근거 줄을 지우고 주석에 확인 날짜를 남깁니다.

## 원본 구성이 바뀌었을 때의 순서

1. 새 원본의 제목 줄만 뽑아 옛 동기화본과 견줍니다. `grep -n '^#' content/synced/portfolio.md`
2. 사이트가 읽는 형식(절 번호, 머리 네 줄, 표)이 어디서 달라졌는지 적습니다.
3. 지금 화면에 보이는데 새 원본에 없는 내용을 목록으로 만듭니다. 옛 동기화본은 `git show main:content/synced/portfolio.md`로 봅니다. 목록에서 남길 것을 사람이 정합니다.
4. 동기화 규칙과 그 시험을 먼저 씁니다. 시험은 실제 설정을 작은 가짜 원본에 적용해, 블록이 제자리에 들어가는지와 자리가 없을 때 멈추는지를 봅니다(`scripts/lib/sync.test.mjs`).
5. `npm run sync`, `npm run sync -- --check`.
6. 읽는 코드와 시험을 고칩니다(`scripts/lib/portfolio.test.mjs`의 가짜 원본을 새 형식으로).
7. `npm test`로 근거 줄을 대조하고, 아래 방법으로 어긋난 줄을 한 번에 봅니다.
8. 화면을 1280과 375, 라이트와 다크로 봅니다. `/resume`도 같이 바뀌므로 함께 봅니다.

## 겪은 문제

### 근거 줄 시험이 첫 실패에서 멈춰 전체가 안 보였습니다

- 증상: `sources` 시험이 `home.md`의 한 줄에서 멈춰, 어긋난 줄이 몇 개인지 알 수 없었습니다.
- 원인: 시험이 줄마다 `assert`를 해서 첫 실패에서 끝납니다.
- 해결: 설계 전에 모든 글의 근거 줄을 한 번에 대조하는 짧은 스크립트를 돌렸습니다. 열 개가 나왔고, 여덟 개는 문장이 다듬어진 것, 둘은 절이 없어진 것이었습니다.

  ```bash
  node -e '
  const fs=require("fs"),path=require("path");
  (async()=>{const {parseFrontmatter}=await import("./src/lib/frontmatter.mjs");
  const text=["resume.md","portfolio.md"].map(f=>fs.readFileSync("content/synced/"+f,"utf8")).join("\n");
  const walk=d=>fs.readdirSync(d,{withFileTypes:true}).flatMap(e=>e.isDirectory()?walk(path.join(d,e.name)):[path.join(d,e.name)]);
  for(const f of walk("content/site").filter(f=>f.endsWith(".md")))
    for(const s of parseFrontmatter(fs.readFileSync(f,"utf8"),f).data.sources??[])
      if(!text.includes(s))console.log(f,"::",s)})()'
  ```
- 막는 방법: 원본 구성이 바뀌면 설계 전에 이 대조부터 돌립니다. 화면 글이 아니라 근거만 바뀌는 줄과, 사람에게 물어야 하는 줄을 먼저 나눕니다.

### 같은 첫 줄을 가진 블록 둘을 따로 끼울 수 없었습니다

- 증상: Recueve와 ProWith의 "기술적 결정" 블록을 규칙 둘로 두면 둘째 규칙이 멈춥니다.
- 원인: `insert-before`는 블록의 첫 줄이 글에 이미 있으면 멈춥니다. 규칙은 차례로 적용되므로 첫 규칙이 넣은 제목에 둘째가 걸립니다.
- 해결: ProWith의 표를 그 앞의 다른 블록(쇼핑몰 상세)과 한 규칙으로 묶어 첫 줄이 다르게 했습니다. 규칙의 순서(Recueve 먼저)를 설정 파일 주석에 적었습니다.
- 막는 방법: 블록의 첫 줄은 글 전체에서 하나뿐인 줄로 고릅니다.

### 원문 인라인 SVG가 좁은 화면에서 읽히지 않았습니다

- 증상: 구성도는 폭 700 기준에 글자 10.5~12.5로 그려져, 375 화면에 맞춰 줄이면 글자가 5~6px입니다.
- 원인: 인쇄 폭에 맞춘 그림이고, 폭을 정하던 `style` 속성은 사이트에서 버립니다.
- 해결: 그림을 상자(`.md-figure`)로 감싸 `min-width: 40rem`을 주고 상자 안에서만 옆으로 넘깁니다. 설명 줄은 상자 밖에 둬 넘기지 않습니다. 넓은 표와 같은 방식이라 키보드 초점과 이름도 같이 줍니다(`rehypeFigures`).
- 주의: 처음에는 그림 묶음(`.fig`) 전체에 `overflow-x: auto`를 줬다가 설명 줄까지 같이 밀려 잘렸습니다. 넘기는 상자는 그림만 감쌉니다.
- 확인: E2E가 모바일에서 상자의 `scrollWidth > clientWidth`와 페이지의 가로 넘침 0, 설명 줄이 화면 폭 안인지를 봅니다.

### 첫 칸이 문장인 표에서 둘째 칸이 좁아졌습니다

- 증상: "기술적 결정" 표의 첫 칸이 한 줄로 길게 늘어나 둘째 칸(이유)이 네댓 글자 폭이 되었습니다.
- 원인: `.md td:first-child`는 이름표로 보고 `white-space: nowrap`을 줍니다.
- 해결: 본문 행 가운데 첫 칸의 글이 30자를 넘는 표에만 표시(`md-long-first`)를 붙여 첫 칸도 줄을 바꿉니다(`rehypeLongFirstColumn`). CSS만으로는 글 길이를 고를 수 없습니다.
- 주의: 기준을 20자로 잡았더니 이름과 명령어를 줄바꿈으로 나눈 칸(스킬 표, 이으면 22~24자)까지 걸렸습니다. 30자로 올리고 그 경우를 시험에 넣었습니다.

### 비교판에 넣은 그림이 캡처에 안 찍혔습니다

- 증상: 개발 서버 페이지에 `page.evaluate`로 `<img>`를 넣었는데 캡처에는 없었습니다. 넣은 직후 크기를 재면 정상이었습니다.
- 원인: 페이지를 연 직후에 넣어, 뒤이어 끝난 하이드레이션이 서버가 그린 DOM으로 되돌렸습니다.
- 해결: `load`와 `document.fonts.ready` 뒤 2.5초를 기다린 다음 DOM을 고칩니다.

### 동기화가 원본의 커밋하지 않은 변경에서 멈췄습니다

- 증상: `npm run sync`가 "원본에 커밋하지 않은 변경이 있습니다"로 멈췄습니다.
- 원인: 원본 쪽에서 같은 파일을 고치는 중이었습니다. 동기화는 커밋된 원본만 가져옵니다.
- 해결: 원본이 커밋된 뒤 그 커밋으로 동기화했습니다. 원본이 같은 값을 갖게 되어, 사이트에서만 값을 바꾸려던 규칙은 넣지 않았습니다.
- 막는 방법: 멈추면 `--allow-dirty`로 넘기지 않고, 원본 쪽이 커밋할지 되돌릴지를 먼저 확인합니다.

## 확인 방법

- `npm run sync -- --check`: 동기화 결과물이 원본과 규칙으로 다시 만든 것과 같은지.
- `node --test scripts/lib/sync.test.mjs scripts/lib/portfolio.test.mjs scripts/lib/content.test.mjs`
- `npm run test:e2e`: `/work`의 챕터 수, 그림 수, 좁은 화면의 넘침, 남긴 블록의 제목.
