# 서비스 캡처

> 정함: 2026-10-19 (홈 "운영 중인 서비스" 카드의 Recueve, ProWith 그림을 비교판으로 골라 바꿈)
> 코드: `src/lib/project-images.ts`(`CARD_IMAGES`, `PROJECT_IMAGES`), `src/components/home/service-cards.tsx`, `content/site/projects/*.md`(`cardImageAlt`와 주석)
> 확인: `e2e/home.spec.ts`의 "서비스 카드 세 장", `e2e/work.spec.ts`의 챕터 그림
> 캡처: [design/service-cards](../design/service-cards/)

포트폴리오 사이트에 운영 중인 서비스의 화면을 실을 때의 기준입니다. 다른 사이트를 만들 때도 같은 방식으로 찍습니다. 찍으며 겪은 문제도 함께 둡니다.

## 정한 것

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 카드와 상세를 나눔 | 목록 카드에는 처음 보는 사람이 무슨 서비스인지 알아볼 화면(서비스 첫 화면, 관리자 대시보드)을, 상세 페이지에는 기능이 보이는 화면(레코 상세, 마감 내역)을 씁니다 | 카드 크기에서는 글자가 읽히지 않아, 글자 위주의 기능 화면은 회색 덩어리로 보였습니다. 기능은 큰 그림과 글이 있는 상세 페이지가 보여 줍니다 |
| 너무 튀는 화면은 피함 | 다른 카드보다 색이 훨씬 강한 화면(예: 보라색 그라데이션의 랜딩)은 카드에 쓰지 않습니다 | 세 카드가 나란히 놓이므로 한 장만 눈에 띄면 다른 카드가 묻힙니다. 그래서 Lotto AI는 첫 화면 대신 분석 화면을 그대로 두었습니다 |
| 처음 보는 사람 기준 | 관리자 화면에서는 수당 같은 업무 설정보다 대시보드와 일반 설정 메뉴처럼 누구나 읽는 화면을 고릅니다 | 이 사이트는 해당 업무를 모르는 사람도 봅니다 |
| 개인정보 | 다른 사람 얼굴이 든 썸네일, 회원 이름과 아이디는 틀 밖에 둡니다 | 데모 데이터라도 이름과 얼굴은 실제 사람처럼 읽힙니다. 민감정보 검사는 글자만 읽어 그림 속 이름은 눈으로 확인합니다 |
| 데모에 들어가는 방법 | 서비스에 공개된 데모 버튼(예: ProWith 로그인 창의 DEMO Login)으로만 들어갑니다. 비밀번호는 입력하지 않고, 화면만 보고 값은 바꾸지 않습니다 | 누구나 같은 화면을 다시 찍을 수 있고, 데모 데이터가 바뀌지 않습니다 |
| 틀 | 1280×800(1.6 비율)으로 찍습니다. 내용이 더 필요하면 비율을 지킨 채 넓게(1920×1200) 찍습니다 | 카드는 그림을 위쪽 왼쪽 기준으로 잘라 채웁니다(`object-cover object-left-top`). 비율이 같아야 세 카드에서 잘리는 양이 같습니다 |
| 파일 | 그라데이션이 많은 화면은 JPEG(품질 90), 평면 화면은 PNG로 저장합니다 | Recueve 첫 화면은 PNG로 595KB, JPEG로 191KB였습니다. 사이트에는 Next.js가 줄인 그림이 나가지만 저장소 크기가 줄어듭니다 |
| 기록 | 그림마다 주소, 틀, 들어간 방법, 피한 것을 서비스 글의 주석에 적습니다 | 다음에 바꿀 때 같은 틀로 다시 찍기 위해서입니다 |

## 만드는 방법

- **찍기**: Playwright로 서비스를 열어 찍습니다. 비교할 때는 개발 서버의 실제 카드에 후보 그림만 끼워 넣어(`img.src`를 data URL로 바꿈) 카드 크기로 봅니다. 코드는 고르기 전까지 고치지 않습니다.
- **마우스를 올린 상태**: 접은 사이드바의 아이콘을 하나씩 `hover()`하며 원하는 팝업 메뉴의 글자(예: "보상플랜 설정")가 보이는 아이콘을 찾고, 그 상태로 찍습니다. 마우스를 올리지 않으면 팝업이 닫힙니다.
- **카드와 상세를 나누는 코드**: 그림 모음을 둘(`CARD_IMAGES`, `PROJECT_IMAGES`)로 두고, 카드의 대체 글은 `cardImageAlt`가 있으면 그것을, 없으면 상세와 같은 `imageAlt`를 씁니다.

## 겪은 문제와 주의할 점

### 대시보드 아래쪽에 회원 이름이 있음 (겪음)

- ProWith 데모 대시보드는 위쪽이 통계와 차트이고, 아래쪽 "최근 가입 회원"과 "최근 매출" 목록에 회원 이름과 아이디가 나옵니다. 처음 홈을 만들 때(2026-10-14)는 이 때문에 대시보드를 피하고 마감 내역을 썼습니다.
- 각 카드의 위치를 재어(`getBoundingClientRect`) 이름 목록이 틀 아래에서 시작하는지 확인하고 찍었습니다(1920×1200 틀의 아래 끝 1200, 목록 제목 1219).
- 틀을 더 늘리거나 아래로 내리면 이름이 들어옵니다. 다시 찍을 때도 위치를 재어 확인합니다.

### 1280×800에서 파이 차트가 잘림 (겪음)

- 대시보드의 파이 차트가 800 아래에서 시작해 제목만 보였습니다.
- 높이만 늘리면 비율이 바뀌어 카드에서 잘리는 양이 달라집니다. 비율을 지킨 1920×1200으로 찍어 통계, 막대 차트, 파이 차트가 모두 들어갔습니다.

### 넓게 찍으면 카드에서 글자가 작아짐 (주의)

- 1920 폭 그림을 카드 폭(약 23rem)으로 줄이면 다른 1280 폭 그림보다 글자와 팝업 메뉴가 작게 보입니다. 팝업 메뉴는 카드에서 검은 상자로만 보이고 글자는 읽히지 않습니다.
- 차트처럼 모양으로 읽히는 것을 넣을 때만 넓게 찍습니다.

### 데모 데이터 하나 때문에 차트가 비어 보임 (겪음)

- 일별 매출 차트의 가로축이 마지막 매출일까지 늘어나, 맨 끝의 매출 하나만 높고 나머지 날은 비어 보였습니다.
- 데모 데이터에서 그 매출을 지우고 같은 틀로 다시 찍었습니다. 차트가 들어가는 화면은 찍기 전에 데모 데이터가 고르게 퍼져 있는지 봅니다. 데이터는 화면 밖에서 데모 관리자가 정리하고, 캡처하는 쪽은 값을 바꾸지 않습니다.

### 움직이는 첫 화면은 찍을 때마다 다름 (주의)

- Recueve 첫 화면은 카드들이 떠다녀, 찍을 때마다 자리가 조금씩 다릅니다. 고른 캡처 파일을 그대로 쓰고, 다시 찍으면 비교판으로 다시 봅니다.

## 확인할 것

- 카드 1280과 375, 라이트와 다크 캡처를 봅니다. 그림 속에 이름, 얼굴, 공개 연락처가 아닌 이메일이 없는지 눈으로 봅니다.
- 상세 페이지의 그림이 그대로인지 봅니다(카드만 바꿨을 때).
- E2E가 카드 그림의 대체 글(`cardImageAlt ?? imageAlt`)과 상세 그림의 대체 글(`imageAlt`)을 확인합니다.
