# Jake English 페이지에 저장소 링크 넣기 설계

> 작성: 2026-11-18 (superpowers brainstorming)
> 상태: 사용자가 비교판에서 두 자리를 골랐습니다(위 C, 아래 A).
> 표시: 「(AI 판단)」은 사용자가 정하지 않고 에이전트가 정한 것입니다. 표시가 없는 결정은 사용자가 정한 것입니다.

## 왜 하나

`/ai/jake-english`에서 앱의 코드와 기록(스펙, 계획, PR)을 바로 볼 수 있게, 공개 저장소 https://github.com/BuffSo/jake-english 로 가는 링크를 둡니다. 지금 페이지에는 영상 링크와 `/ai`로 돌아가는 링크만 있어, 페이지에서 말하는 작업 방식(스펙, 계획, PR 78개)을 직접 확인할 길이 없습니다.

## 목표

- 맨 위(영상 바로 아래)와 맨 아래(끝 버튼 줄) 두 곳에서 저장소로 갑니다. 둘 다 새 창으로 열립니다.
- 링크 주소와 맨 위 글은 사이트 전용 글 `content/site/jake-english.md`에 둡니다. 코드에 주소를 박지 않습니다.
- 바깥 링크 클릭은 지금 방식 그대로 방문 통계의 `outbound`로 잡힙니다.

## 하지 않을 것

- 영상, 이야기 4컷, 본문, 기술 스택의 글과 모양은 바꾸지 않습니다.
- `/ai` 맨 위의 Jake English 띠에는 링크를 더하지 않습니다.
- 맨 위와 맨 아래 클릭을 통계에서 나누지 않습니다. 지금 영상 링크(썸네일과 끝 버튼)도 나누지 않습니다. (AI 판단)

## 하면 안 되는 것

- 영상 아래부터 이야기 4컷 선까지의 간격이 달라지면 안 됩니다.
- 375 화면에서 끝 버튼 세 개가 두 줄로 꺾이면 안 됩니다.

## 지금 코드에서 확인한 것

- **페이지**: `src/app/ai/jake-english/page.tsx`. 영상은 `ExternalLink` 하나(썸네일과 아래 한 줄)이고 아래 여백 `mb-10 lg:mb-14`를 이 링크가 갖습니다. 끝 버튼 줄은 `ButtonLink` 둘(「영상 보기」 채운 버튼, 「AI로 일하는 방식」 테두리 버튼)이고 버튼 사이 0.5rem, `flex-wrap`입니다.
- **글**: 영상은 `video: { href, caption }`으로 주소와 영상 아래 한 줄의 글을 사이트 전용 글에 두고, 줄 끝 화살표(→)와 끝 버튼의 「영상 보기」는 화면 코드에 있습니다. 형은 `src/lib/content.ts`의 `JakeEnglish`입니다.
- **바깥 링크**: `ExternalLink`가 `target="_blank"`, `rel="noreferrer"`, 화면 읽기용 「(새 창)」을 붙입니다. `ButtonLink`는 `http(s)` 주소면 `ExternalLink`로 그리고 ↗를 붙입니다.
- **방문 통계**: `src/components/outbound-clicks.tsx`가 문서 전체의 클릭을 받아 `outboundEvent(a.href, location.href)`로 값을 만듭니다. 두 링크 모두 `{ to: "github.com/BuffSo/jake-english", from: "/ai/jake-english" }`로 잡힙니다(2026-11-18 node로 확인). 링크마다 코드를 달 필요가 없습니다.
- **같은 말**: `/ai`의 「이 사이트」 항목(`content/site/ai/this-site.md`)은 저장소 버튼을 「저장소」라고 씁니다.
- **저장소**: 공개이고 열면 200입니다(2026-11-18 확인).

## 방법

비교판(지금 화면 위에 CSS를 얹어 1280, 375로 찍음)에서 세 안을 견줬습니다.

| 안 | 자리와 모양 | 장점 | 단점 |
|---|---|---|---|
| **A. 끝 버튼 「저장소 ↗」 (고름)** | 끝 버튼 줄의 가운데, 테두리 버튼 | `/ai` 「이 사이트」의 저장소 버튼과 같은 말이고, 375에서도 세 버튼이 한 줄에 듭니다 | 페이지를 끝까지 읽어야 보입니다 |
| B. 끝 버튼 「GitHub 저장소 ↗」 | A와 같은 자리 | 어디로 가는지 더 분명합니다 | 375에서 버튼 줄이 두 줄로 꺾입니다 |
| **C. 영상 아래 글 링크 「GitHub 저장소 ↗」 (고름)** | 영상 아래 한 줄 바로 밑, 같은 작은 회색 글 | 첫 화면에서 보입니다(구현 뒤 확인: 375×812 모바일은 첫 화면 안, 1280×800 데스크톱은 첫 화면 바로 아래) | 영상 블록이 한 줄 길어집니다 |

main 세션은 A 하나를 추천했고, 사용자가 C도 함께 넣자고 했습니다. 처음 화면에서 바로 보이는 자리(C)와 다 읽은 뒤 가는 자리(A)를 둘 다 둡니다.

## 정한 것

### 맨 위 (C)

- 영상 아래 한 줄(「소개 영상 · 3분 17초 · YouTube에서 보기 →」) 바로 아래에 글 링크 「GitHub 저장소 ↗」를 한 줄 둡니다.
- 영상 아래 한 줄과 같은 글자: 0.875rem, `muted`, 마우스를 올리면 `fg`. 새 창으로 열립니다.
- 누르기 쉽게 높이 2.75rem 이상(`min-h-11`, 돌아가기 링크와 같음). 영상 아래 한 줄과 사이 0.25rem(시안 그대로).
- 영상 링크가 갖던 아래 여백(2.5rem, 데스크톱 3.5rem)을 영상과 저장소 링크를 감싼 블록으로 옮겨, 이야기 4컷 선까지의 간격을 지금과 같게 둡니다.
- 누를 수 있는 곳은 글 폭까지입니다. 줄 전체를 링크로 만들지 않습니다. (AI 판단)

### 맨 아래 (A)

- 끝 버튼 줄을 「영상 보기 ↗」(채운 버튼) · 「저장소 ↗」(테두리 버튼) · 「AI로 일하는 방식」(테두리 버튼) 순서로 둡니다. `ButtonLink`의 outline 모양 그대로입니다.

### 글의 자리 (AI 판단)

영상과 같은 방식으로 둡니다.

- `content/site/jake-english.md`의 머리말에 `repo: { href, caption }`을 `video` 바로 뒤에 둡니다. `href`는 저장소 주소, `caption`은 맨 위 글 「GitHub 저장소」입니다.
- 줄 끝 ↗와 끝 버튼의 「저장소」는 화면 코드에 둡니다. 영상의 →와 「영상 보기」가 화면 코드에 있는 것과 같습니다.
- `src/lib/content.ts`의 `JakeEnglish`에 `repo: { href: string; caption: string }`을 더합니다.

### 테스트 (AI 판단)

`e2e/ai-jake-english.spec.ts`에서 확인합니다. 데스크톱(1280)과 모바일(375) 둘 다 돕니다.

- 맨 위: 「GitHub 저장소」 링크가 하나이고, 주소가 글의 `repo.href`이고, 새 창(`target="_blank"`)이고, 높이가 44px 이상입니다. `main`의 링크 순서에서 영상 링크 바로 다음이고, 이야기 4컷 절보다 앞입니다. 링크 아래부터 이야기 4컷 선까지가 2.5rem(데스크톱 3.5rem)입니다.
- 맨 아래: 끝 버튼 줄의 링크가 「영상 보기」, 「저장소」, 「AI로 일하는 방식」 순서이고, 앞의 둘은 새 창, 「저장소」의 주소가 `repo.href`입니다. 세 버튼의 위 끝이 같아 한 줄에 듭니다.
- 방문 통계는 운영 배포에서만 그려져 E2E로 보지 않습니다. `outboundEvent`의 값은 node로 확인했고, 그 함수의 규칙은 `scripts/lib/outbound.test.mjs`가 이미 확인합니다.
