# `/ai` 다섯째 묶음 "대회 참가" 설계

> 작성: 2026-11-27 (superpowers brainstorming)
> 상태: 사용자가 비교판에서 모양 가(테두리 항목 카드)와 이름 "대회 참가 결과"를 골랐습니다. 같은 날 구현 화면을 보고 이름을 "대회 참가"로 줄였습니다(결과는 카드 안의 "상위 5%"와 결과 줄이 보여 줌).
> 표시: 「(AI 판단)」은 사용자가 정하지 않고 에이전트가 정한 것입니다. 표시가 없는 결정은 사용자가 정한 것입니다.

## 왜 하나

`/ai/axwar`(PR #69)는 주소가 `/ai` 아래라 헤더의 "AI"에 밑줄이 붙습니다. 그런데 `/ai` 페이지에는 그 페이지로 가는 길이 없습니다. 2026-11-23에 대회 결과 띠를 홈과 `/resume`에만 두고 `/ai`에는 싣지 않기로 정했고 PR #69도 그 결정을 따랐습니다. 상세 페이지가 `/ai` 아래에 생긴 지금은 헤더와 페이지가 어긋나 보인다고 사용자가 짚었습니다. 그래서 이 결정을 뒤집습니다.

## 목표

- `/ai` 맨 끝, 지금 네 묶음 뒤에 다섯째 묶음 "대회 참가"를 둡니다. 맨 위 목차에도 다섯째 칸이 생깁니다.
- 묶음 안에는 AX인재전쟁 카드 하나를 둡니다. 카드의 "자세히 보기"가 `/ai/axwar`로 갑니다.
- 앞으로 다른 대회에 참가하면 이 묶음에 카드를 하나씩 더합니다. 이름에 "참가"를 넣고 카드 모양을 고른 이유입니다. 지금 글에는 다른 대회를 쓰지 않습니다.

## 하지 않을 것

- 홈과 `/resume`의 대회 결과 띠는 그대로 둡니다. `/ai`에는 띠가 아니라 묶음으로 넣습니다.
- `/ai` 맨 위 입구 상자 두 개(CASE, APP)는 그대로 둡니다.
- `/ai/axwar` 페이지는 끝 버튼 줄만 고칩니다(아래 "추가 요청"). 머리와 인증서 카드는 그대로입니다.
- 카드에 새 사실을 쓰지 않습니다. `/ai/axwar`의 글(`content/site/axwar.md`)에 있는 사실만 씁니다. 대회 기간("하루 남짓", "이틀")도 쓰지 않습니다.

## 하면 안 되는 것

- 다른 대회를 지어내거나 "앞으로 더 참가할 예정" 같은 문장을 쓰지 않습니다.

## 지금 코드에서 확인한 것

- `/ai`(`src/app/ai/page.tsx`)는 `content/site/ai-page.md`의 `groups`와 `content/site/ai/*.md`의 항목(`group`, `order`)으로 묶음을 그립니다. 묶음 번호(`01 / 04`)와 마지막 묶음의 아래 여백은 묶음 수로 계산합니다. 묶음을 하나 더하면 번호가 `/ 05`로 바뀝니다.
- 항목 모양은 둘입니다. 상세(`AiItem`, 그림이 있는 두 칸)와 짧은 카드(`AiShort`, 테두리 상자에 문제·만든 것·결과 한 줄씩, 숫자 하나, "자세히 보기")입니다. 짧은 카드는 원문이 다른 페이지에 있는 항목에 씁니다(지금은 `/work`의 AI 절로 가는 ProWith 하네스, Recueve AI 자동 채움).
- 목차(`src/components/ai/ai-index.tsx`)는 데스크톱에서 `lg:grid-cols-4`로 묶음 네 칸입니다.
- 시험: `scripts/lib/content.test.mjs`의 "AI 작업 글" 시험은 짧은 카드의 `more`가 `/work#…-ai`이기를 요구합니다. `e2e/ai.spec.ts`의 짧은 카드 시험은 `more`의 `#` 뒤 절이 화면에 보이는지 봅니다. 목차 시험은 `ai-page.md`와 항목 글에서 기대값을 읽어 새 묶음도 저절로 봅니다.

## 방법

비교판(개발 서버의 `/ai`에 시안을 얹어 1280과 375로 찍음)에서 지금 화면과 두 안을 견줬습니다.

| 안 | 모양 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **가. 항목 카드 (고름)** | ProWith 하네스, Recueve AI 자동 채움과 같은 테두리 카드. 문제·만든 것·결과 한 줄씩, 숫자 "상위 5%", "자세히 보기" | `/ai` 안 항목 모양이 두 가지 그대로이고, 대회 결과도 다른 작업과 같은 기준으로 읽힙니다. 대회가 늘면 카드를 하나씩 더하기 좋습니다 | 그림이 없어 "상위 5%"가 숫자 칸 크기로만 보입니다 |
| 나. 요약 상자 | 대회 이름, 큰 "상위 5%", 참가자 줄, 인증서 그림, "자세히 보기" | 결과와 증빙이 바로 보입니다 | 이 묶음만 모양이 다르고, `/ai/axwar` 첫 화면을 한 번 더 보여 주는 셈입니다 |

섹션 이름은 "대회 결과"(추천), "외부 평가", "결과로 보여 준 것"을 견줬고, 사용자가 다른 대회도 담을 수 있게 "대회 참가 결과"로 정했다가, 구현 화면을 본 뒤 "대회 참가"로 줄였습니다. 조건은 목차 다섯째 칸에서 1024와 1280에 한 줄로 드는 것이었고(꺾이면 "참가한 대회"), 재 보니 두 폭 모두 한 줄입니다(글 폭 102px, 칸 폭 179px와 230px, 2026-11-27 개발 서버).

글을 둘 곳은 두 가지를 견줬습니다. (AI 판단)

| 안 | 내용 | 고른 이유 |
|---|---|---|
| **새 항목 글 `content/site/ai/axwar.md` (고름)** | 다른 항목처럼 항목 글 하나를 두고 `group: contest`로 묶습니다 | 지금 코드가 그대로 그리고, 대회가 늘면 글 하나만 더합니다. 숫자와 문장이 `/ai/axwar` 글과 어긋나지 않는지는 내용 시험이 봅니다 |
| `content/site/axwar.md`에서 코드로 카드를 만듦 | 페이지 글에 카드 칸을 더하고 `getAiWorks()`가 끼워 넣음 | 사실이 한 파일에 있지만, 항목 목록을 읽는 길이 둘이 되고 대회가 늘 때마다 코드를 고쳐야 합니다 |

## 정한 것

### 묶음

- 이름 "대회 참가", id `contest`(`/ai#contest`). (id는 AI 판단)
- 자리는 맨 끝, 번호 `05 / 05`입니다. 앞 네 묶음의 번호도 `/ 05`가 됩니다.
- 묶음 사이 선, 여백, 제목 크기는 다른 묶음과 같습니다([03-design.md](../../03-design.md#f3에서-정한-값)).

### 카드 (모양 가)

짧은 카드(`AiShort`)를 그대로 씁니다. 새 컴포넌트와 새 값은 없습니다.

```
05 / 05
대회 참가
┌──────────────────────────────────────────────────────────┐
│ CONTEST · AX인재전쟁 온라인 1회차                          │
│ AX인재전쟁 삼일PwC 과제                    ───────────     │
│ 문제    가상 화장품 그룹에서 …               상위 5%        │
│ 만든 것 판단부터 승인과 처리까지 …           참가자 2,916명 중 · 2026.11 │
│ 결과    참가자 2,916명 중 상위 5%에 …       (자세히 보기)   │
└──────────────────────────────────────────────────────────┘
```

- 항목 slug `axwar`(`/ai#axwar`), 순서 10(맨 끝). (AI 판단)
- "자세히 보기"는 `/ai/axwar`로 같은 창에서 갑니다. ↗가 없습니다(사이트 안 링크).
- 숫자 칸은 `/ai/axwar` 글의 결과(`result`)와 참가자 줄(`participants · date`)을 그대로 씁니다.
- 카드 글은 아래 초안이고, **구현 화면을 보여 줄 때 문구만 따로 확인받습니다**(사용자 요청). 모두 `/ai/axwar` 본문 문장에서 줄인 것입니다.

| 칸 | 초안 | 출처 (`content/site/axwar.md`) |
|---|---|---|
| 머리글 | CONTEST · AX인재전쟁 온라인 1회차 | `contest`. 비교판의 `AWARD`는 묶음 이름에 "참가"를 넣은 뜻에 맞춰 바꿈 (AI 판단, 문구 확인 때 함께 봄) |
| 이름 (h3, 목차 링크) | AX인재전쟁 삼일PwC 과제 | `contest` |
| 문제 | 가상 화장품 그룹에서 부서마다 다른 숫자로 판단해 결정이 늦어집니다. | 본문 셋째 문단 |
| 만든 것 | 판단부터 승인과 처리까지 실제로 이어지는 AI 운영 시스템입니다. Orca로 기능을 나눠 git worktree 여러 개에서 동시에 개발했습니다. | 본문 셋째, 넷째 문단 |
| 결과 | 참가자 2,916명 중 상위 5%에 들었고, 결과물 심사 상위 100명 보상도 받았습니다. | 본문 첫 문단과 덧붙임 줄(`extra`) |
| 숫자 | 상위 5% / 참가자 2,916명 중 · 2026.11 | `result`, `participants`, `date` |

### 목차

- 데스크톱은 네 칸을 다섯 칸으로 나눠 한 줄을 유지합니다. 1024에서도 한 줄이고, 다섯째 칸의 항목 이름 "AX인재전쟁 삼일PwC 과제"만 두 줄로 꺾입니다. 모바일은 지금처럼 묶음마다 한 줄이라 줄이 하나 늘어납니다. (AI 판단, 비교판에 캡처를 보임)

### 시험

- 내용 시험(`scripts/lib/content.test.mjs`)
  - 짧은 카드의 `more`는 `/work`의 AI 절이거나 `/ai` 아래 페이지(`/ai/<이름>`, 페이지 파일이 있음)입니다.
  - 대회 카드의 숫자는 `/ai/axwar` 글의 `result`, `participants`, `date`와 같습니다.
  - 대회 카드의 `sources`(문장 조각)는 `/ai/axwar` 본문과 덧붙임 줄(`extra`)에 그대로 있습니다. 지금 `sources` 시험은 동기화한 이력서와 포트폴리오를 보는데, `more`가 `/ai/axwar`인 카드는 그 페이지 글을 봅니다. (AI 판단)
- E2E(`e2e/ai.spec.ts`)
  - 짧은 카드 시험이 `/ai/axwar`처럼 `#`이 없는 주소도 따라가, 그 페이지의 h1이 보이는지 봅니다.
  - 데스크톱(1024, 1280)에서 목차 칸이 모두 한 줄에 있고, 묶음 이름이 한 줄로 드는지 봅니다(첫 칸 이름과 높이가 같음).
  - 목차, 묶음 번호, 항목 링크는 지금 시험이 새 글에서 기대값을 읽어 봅니다.

## 추가 요청: `/ai/axwar` 끝 버튼 되살리기

같은 날 사용자가 이 PR에 함께 넣어 달라고 했습니다. 새 비교판 없이 구현한 화면으로 확인받습니다.

- `/ai/axwar` 끝 버튼 줄을 PR #69 처음 구현 때의 짜임으로 되돌립니다: "인증서 보기 ↗"(채운 버튼, 새 창, 인증서 주소) + "AI로 일하는 방식"(테두리 버튼).
- 머리 아래 인증서 카드는 그대로 두고, 카드 근처에는 버튼을 더하지 않습니다. 인증서로 가는 링크는 카드와 끝 버튼 두 개가 됩니다.
- 버튼 문구는 처음 구현 때의 값 `cert.cta`("인증서 보기")를 `content/site/axwar.md`에 되살려 씁니다. `ButtonLink`가 바깥 주소라 새 창과 ↗를 저절로 붙입니다.
- 시험: `e2e/ai-axwar.spec.ts`의 끝 링크 시험을 "main의 링크는 돌아가기, 인증서 카드, 끝 줄의 인증서 보기와 AI로 일하는 방식 넷"으로 고치고, 끝 버튼이 새 창이며 본문 마지막 문단보다 아래인지 봅니다. 인증서 카드를 찾는 방법은 같은 주소의 링크가 둘이 되므로 그림이 든 링크로 좁힙니다.
- 문서: IA `/ai/axwar` 절의 구성과 "끝 링크", 디자인 문서 AX인재전쟁 절의 끝 버튼 줄 문장, `docs/design/ai-axwar/`의 페이지 캡처 네 장(`page-1280`, `page-375`, `page-1280-dark`, `page-375-dark`)을 다시 찍습니다. 첫 화면 캡처는 끝 줄이 보이지 않아 그대로입니다.

## 같이 하는 후속 작업 (`docs/todo/20261127_01_todo_axwar_followups.md`)

1. **띠의 기간 시험 넓히기**: "대회 결과 띠는 /ai/axwar로 가고, 둘째 줄에 기간을 쓰지 않는다" 시험이 `title`과 `detail`을 함께 보고, 숫자로 쓴 기간도 막게 합니다(`/이틀|하루|\d+\s*(일|시간)/`).
2. **가이드에 교훈 두 가지**
   - [검색과 공유 정책](../../guide/SEO_검색과_공유_정책_20261017.md)의 "페이지를 더할 때"에 5번을 더합니다: 새 페이지의 E2E는 응답이 200인지 먼저 봅니다. 가로 스크롤 시험과 캡처 시험이 페이지가 없을 때(404 화면)도 통과했기 때문입니다.
   - [AI 사례 가이드](../../guide/CONTENT_AI_사례_20261020.md)에 새 절 "바깥 증빙을 링크 카드로 보여 줄 때 (AX인재전쟁, 2026-11-27)"를 둡니다: 그 페이지의 공유 그림(og:image)을 저장소에 받아 두고, 카드 제목은 이름이 없는 그림 설명(og:image:alt)을 씁니다. 이유와 확인 방법도 함께 씁니다. 가이드 색인(`docs/guide/README.md`)의 두 줄도 고칩니다.
3. **첫 화면 여유**: 이 작업은 `/ai/axwar` 머리를 바꾸지 않아 고칠 것이 없습니다. todo가 닫혀도 기준이 남도록 [03-design.md](../../03-design.md#ax인재전쟁-페이지에서-정한-값)에 한 줄을 더합니다: 1366×768 노트북(쓸 수 있는 높이 약 650px)과 메신저 안 375×667(약 550px)에서는 지금도 카드 제목이 첫 화면 아래로 잘리고 그림 윗부분만 보이므로, 카드 위에 무엇을 더할 때 이 여유를 먼저 봅니다.
4. **주석 하나**: `src/lib/content.ts`의 `Axwar.extra` 주석 "참가자 줄 아래의 덧붙임 한 줄"을 지금 자리 "인증서 카드 아래의 덧붙임 한 줄"로 고칩니다(PR #69 리뷰에서 남은 것).

todo 파일은 일을 끝내는 커밋에서 상태 줄을 완료로 고쳐 함께 넣습니다. 3번은 확인 결과만 상태 줄에 적습니다.
