# /work를 새 포트폴리오 원본에 맞추기 설계

> 작성: 2026-11-23 (superpowers brainstorming)
> 상태: 화면 모양 세 가지는 비교판에서 정했습니다. 사이트 전용 글의 문구 두 줄은 후보를 보내고 답을 기다립니다(아래 「아직 정하지 않은 것」).
> 표시: 「(AI 판단)」은 사용자가 정하지 않고 에이전트가 정한 것입니다. 표시가 없는 결정은 사용자가 정한 것입니다.

## 왜 하나

포트폴리오 원본이 2026-11-23에 새 구성으로 바뀌었습니다. 프로젝트 상세가 앞으로 오고, 프로젝트마다 구성도(인라인 SVG)가 생겼고, Jake English가 네 번째 프로젝트로 들어갔습니다. `/work`는 옛 구조(절 번호, 굵은 기간 줄, 「보시는 방법」 절)를 전제로 원문을 읽기 때문에, 새 원본을 동기화하면 `PortfolioError`로 빌드가 멈춥니다.

`/work`를 고치는 목적은 새 포트폴리오의 구성도를 싣는 것입니다.

## 목표

- `/work`의 모양은 지금 그대로 둡니다. 서비스 챕터, 챕터 아래에 붙는 절, 의뢰받아 만든 사이트 순서입니다.
- 새 원본의 구성도 넷과 Recueve 자동 채우기 흐름도 하나를 원문 자리에 그대로 싣습니다.
- Jake English 챕터(원문 2-4)를 네 번째로 더합니다. PRD F2 범위에 Jake English를 더합니다.
- 문장은 원문 그대로 그립니다(ADR-0003). 홈페이지는 인쇄본보다 자세하게 보여 줍니다. 원본이 인쇄본 분량 때문에 뺀 상세는 동기화 규칙(`scripts/sync.config.mjs`)으로 사이트에만 남깁니다. 이력서의 「본인의 강점」과 자격증을 남긴 것과 같은 방식입니다.
- 같은 날 원본을 따라가야 하는 사이트 전용 글을 같은 PR에서 맞춥니다.

## 하지 않을 것

- 새 원본에 새로 생긴 절은 싣지 않습니다: 「6. 협업 - 동료 평가」, 5-2와 5-3(운영 이슈 두 건), 3-2(Jake English 작업 방식).
- 표지의 태그라인과 분야별 기술 표, 1절의 표 자체는 싣지 않습니다. 1절 표에서는 소개 문장과 「보시는 방법」 칸만 읽습니다. (AI 판단)
- PDF 내려받기와 인쇄 버튼은 두지 않습니다.
- 홈의 서비스 카드에는 Jake English를 더하지 않습니다. Jake English는 `/ai` 맨 위 띠와 `/ai/jake-english`에 이미 있습니다. (AI 판단)
- Jake English 챕터에서 `/ai/jake-english`로 가는 링크는 더하지 않습니다. 원문에 없는 링크입니다.
- `/ai`의 「ProWith 운영 하네스」 카드 이름은 바꾸지 않습니다.

## 하면 안 되는 것

- 홈 카드의 `/work#recueve`, `/work#prowith`, `/work#lotto-ai`와 `/ai`, `/ai/case`가 가리키는 `/work#prowith-ai`, `/work#recueve-ai`가 깨지면 안 됩니다.
- 원본 맨 위의 인쇄용 `<style>` 규칙이 페이지에 들어오면 안 됩니다.
- 375 화면에서 페이지에 가로 스크롤이 생기면 안 됩니다. 구성도는 자기 상자 안에서만 넘깁니다.
- `content/synced/`를 손으로 고치면 안 됩니다. 원본은 `npm run sync`로만 가져옵니다.
- 원본 저장소의 파일은 고치지 않습니다. 사이트에만 남길 글은 동기화 규칙에 둡니다.

## 새 원본에서 확인한 것

- 절 순서: 1 한눈에 보기 → 2 프로젝트 상세(2-1 ~ 2-4) → 3 AI 활용 - 개발(3-1 ProWith, 3-2 Jake English) → 4 AI 활용 - 제품 → 5 성능 개선과 운영 이슈 해결(5-1 ~ 5-3) → 6 협업 - 동료 평가.
- 상세 절의 둘째 줄은 `기간 | 역할 | 🔗 주소`입니다. 기간은 굵지 않습니다. Jake English 줄은 주소가 둘이고 각각 뒤에 괄호로 이름이 붙습니다(`주소 (소개 영상) · 주소 (공개 저장소)`).
- 「보시는 방법」 절이 없어지고 1절 HTML 표(`table.glance`)의 셋째 칸이 되었습니다. 표의 한 줄이 한 프로젝트이고, 둘째 칸 「무엇인가」의 첫 줄은 한 줄 소개입니다.
- 그림은 `<div class="fig">` 안의 인라인 SVG와 `<sub>` 설명 한 줄입니다. SVG는 `viewBox` 폭 700, 글자 크기 10.5 ~ 12.5이고, 바탕과 색이 SVG 안에 들어 있습니다. 폭과 가운데 정렬은 `style` 속성에 있어 사이트에서는 지워집니다.
- 맨 위 `<style>` 한 줄은 인쇄용입니다. `/work`가 읽는 절 밖(1절 앞)에 있지만, `/resume`처럼 원문을 통째로 그리는 곳이 생기면 들어옵니다.
- 옛 원본의 이미지 두 장(조직도 미니맵, 계정 전환기)과 「3절 참조」, 레거시 전환 인용 줄은 새 원본에 없습니다. `work.md`의 규칙 여덟 개 가운데 「앞의 하네스가」 하나만 남습니다.
- 2-3의 마지막 불릿은 「…병목을 하나씩 잡았습니다(5-1)」로 절 번호를 가리킵니다.

## 방법

세 가지를 견줬습니다.

1. **지금 구조를 새 원본에 맞춘다(고름).** 챕터마다 상세 절 하나와 뒤에 붙일 절 하나를 `work.md`가 정하는 지금 방식을 그대로 쓰고, 읽는 규칙만 새 형식에 맞춥니다. 화면 모양과 앵커가 그대로이고 바뀌는 코드가 가장 적습니다.
2. **원문 절 순서대로 페이지를 다시 그린다.** 규칙은 거의 없어지지만 페이지 모양과 앵커가 모두 바뀝니다. 모양을 그대로 둔다는 결정과 맞지 않습니다.
3. **사이트용 글을 따로 쓴다.** 원문과 두 벌이 되어 어긋납니다. ADR-0003과 맞지 않습니다.

## 설계

### 챕터 구성 (`content/site/work.md`)

| 챕터 | id | 본문 | 뒤에 붙는 절 | 붙는 절의 id |
|---|---|---|---|---|
| 01 Recueve | `recueve` | 2-1 | 「4. AI 활용 - 제품」 | `recueve-ai` |
| 02 ProWith | `prowith` | 2-2 | 「3. AI 활용 - 개발」에서 3-2 앞까지(첫 문장과 3-1) | `prowith-ai` |
| 03 GENYS Lotto AI | `lotto-ai` | 2-3 | 「5-1. GENYS Lotto AI 성능 개선 - …」 | `lotto-ai-performance` (AI 판단) |
| 04 Jake English | `jake-english` | 2-4 | 없음 | |

- 챕터 설정의 `ai`, `aiUntil`, `howToView`를 없애고 `after: { section, until?, id }`로 바꿉니다. 붙는 절이 AI 절만이 아니게 되었기 때문입니다. (AI 판단)
- 붙는 절의 제목은 원문 제목에서 번호만 뗍니다(「AI 활용 - 개발」, 「GENYS Lotto AI 성능 개선 - 세 번에 걸쳐 다른 병목을 잡았습니다」). 붙는 절 안의 소제목도 번호를 뗍니다(「ProWith - 업체마다 되풀이되는 작업을 스킬로 고정」).
- 제목 단계: 챕터 이름 h2, 붙는 절 제목 h3, 그 안의 소제목은 h4부터입니다. ProWith는 3-1이 h4, 「무엇을 자동화했나」가 h5가 되어 `.md h5` 모양을 더합니다. (AI 판단)
- 목차는 다섯 칸(챕터 넷과 의뢰받아 만든 사이트)입니다. 챕터 번호는 `work.md`의 챕터 순서로 매깁니다(「04 / 04 · JAKE ENGLISH」).
- 머리 소개는 새 원본 1절 문장 「직접 설계하고 개발한 프로젝트 네 개입니다. 서비스 세 곳은 지금 열어보실 수 있습니다.」로 바꿉니다. 뒤의 사이트 전용 문장은 그대로입니다. (AI 판단)

### 사이트에서만 고치는 곳

규칙은 지금처럼 정확히 한 번 맞아야 하고, 대상이 사라지면 빌드와 시험이 멈춥니다.

- Recueve: 4절 첫 문단(「앞의 하네스가 …」)을 뺍니다. 이 페이지에서는 Recueve가 먼저 나옵니다(지금과 같음).
- GENYS Lotto AI: 2-3의 「(5-1)」을 「(아래 성능 개선)」으로 바꿉니다. 절 번호가 페이지에 없기 때문입니다. (AI 판단)
- ProWith: 큰 글씨 첫 줄은 1절 표의 「무엇인가」 첫 줄(「보상플랜과 쇼핑몰을 설정으로 켜고 끄는 MLM 정산 솔루션 (멀티테넌트)」)을 쓰고, 원문 인용 세 문장은 본문 맨 앞에 인용 상자로 그대로 둡니다. 챕터 설정 `lead: glance`로 켭니다. 옛 replace 규칙은 없앱니다. 표의 문장은 끝의 「(멀티테넌트)」까지 원문 그대로 씁니다. 홈 서비스 목록의 소개에는 괄호가 없으므로, 두 문장이 같은지 보던 시험은 큰 글씨가 홈의 소개로 시작하는지 보도록 고칩니다. (AI 판단)
- 이미지 규칙 넷과 「3절 참조」 규칙은 대상이 없어져 지웁니다.

### 원문 읽기 (`src/lib/portfolio.mjs`)

- `parseDetail`: 기간이 굵지 않은 줄을 읽습니다. 주소는 ` · `로 나눠 `links: { url, label }[]`로 돌려줍니다. 괄호가 없으면 `label`은 null입니다. 기간에 `*`가 있거나 주소 형식이 다르면 멈춥니다.
- `glance(md, 이름)`: 1절 표에서 그 프로젝트의 줄을 찾아 「무엇인가」 첫 줄과 「보시는 방법」 칸(HTML 그대로)을 돌려줍니다. 줄이 없거나 둘 이상이면 멈춥니다. `howToView`를 대신합니다.
- `composeChapters`: 위 챕터 구성대로 만들고 `after: { id, title, body } | null`을 돌려줍니다.
- 사이트에만 남긴 블록은 동기화 결과물에 이미 들어 있으므로 따로 읽는 규칙을 두지 않습니다. 다른 본문과 똑같이 그립니다.

### 사이트에만 남기는 블록 (`scripts/sync.config.mjs`)

원본은 2026-11-23에 인쇄본 분량에 맞춰 프로젝트 상세를 줄였습니다. 줄이면서 빠진 내용 가운데 구성도나 새 문장에 같은 말이 없는 것을 `insert-before` 규칙으로 되살립니다. 글은 지우기 전의 원문 그대로이고, 겹치는 줄만 뺍니다. `reason`은 「원본은 2026-11-23에 뺐지만 사이트의 포트폴리오에는 남긴다 (본인 결정 2026-11-23, ADR-0003)」입니다.

| 챕터 | 끼우는 자리 | 되살리는 것 | 출처 |
|---|---|---|---|
| Recueve | 구성도 뒤(「2-2」 제목 앞) | 「기술적 결정」 표 세 줄: EC2 한 대에 컨테이너 5개(RDS 비용, S3 백업), 워커 앱 분리(BullMQ, internal webhook), GitHub Actions의 OIDC 인증 | 원본의 앞선 판 |
| ProWith | 구성도 뒤(「2-3」 제목 앞) | 쇼핑몰 상세 세 불릿(무통장입금과 결제 기록 분리, 관리자 주문 관리, 상품 이미지와 고지 항목), 「동적 시스템 설정 엔진」 두 불릿, 백엔드 두 불릿(다국어와 메뉴 영문명, 조직도 미니맵) | 2026-11-10에 동기화한 판 |
| ProWith | 위 블록에 이어서 | 「기술적 결정」 표 네 줄: 단일 코드베이스, 업체별 컨테이너와 Database, 결제완료 때만 매출 생성, 업체별 GitHub Actions | 원본의 앞선 판 |
| GENYS Lotto AI | 불릿 뒤(「2-4」 제목 앞) | 「로그는 NoSQL인 MongoDB에 분리해서 저장했습니다」 절, 「개발 모드에서 등급별 계정을 선택해 바로 테스트하게 했습니다」 절(이미지와 그 설명 줄은 빼고), 「인프라」 한 줄 | 2026-11-10에 동기화한 판 |

되살리지 않는 것과 이유입니다. (AI 판단)

- Recueve 「기술적 결정」의 토큰 이원화, 예약 표시이름 줄: 새 불릿이 같은 말을 합니다.
- ProWith 「기술적 결정」의 DB 잠금 줄, 옛 쇼핑몰의 결제완료와 DB 잠금 불릿, 옛 「멀티테넌트 아키텍처」 네 불릿, 옛 정산 엔진과 백엔드 숫자 불릿: 새 불릿, 구성도, 되살린 표가 같은 말을 합니다.
- ProWith 인용의 데모 안내 뒷부분(`일 마감` 화면 위쪽 문구, 설정 경로 문구): 앞 절반이 새 인용과 같은 문장이라 떼어 내면 원문을 고쳐 쓰게 됩니다.
- GENYS Lotto AI 성능 개선의 옛 문장들(`globalThis` 싱글톤, `includeStats=false`, 탭 전환 1~2초 → 즉시 등): 5-1이 같은 절을 다듬은 판이라 섞으면 같은 말이 두 번 나옵니다.
- 「AI 활용 - 개발」과 「AI 활용 - 제품」의 옛 문장과 파이프라인 표: 새 원본대로 둡니다.

규칙이 원본과 어긋나면 동기화가 멈춥니다. 끼울 자리의 제목 줄이 한 줄이 아니거나, 블록의 첫 줄이 원본에 돌아오면 멈춥니다(지금 `insert-before`의 동작). ProWith의 두 블록은 규칙 하나로 끼웁니다. Recueve 블록과 첫 줄(「기술적 결정」 제목)이 같아 따로 두면 둘째 규칙이 멈추기 때문입니다.

표 안의 사실이 지금 원본과 어긋나면 지금 원본을 따릅니다. 확인한 결과 어긋나는 곳은 없습니다(S3 백업 30일 보관은 구성도와 같습니다).

### 그림

- 구성도와 흐름도는 원문 자리에 그대로 둡니다.
- `rehypeDropStyle`이 `style` 속성과 함께 `<style>` 요소도 버립니다.
- 그림을 감싸는 상자를 하나 더합니다(`rehypeFigures`가 `.fig` 안의 `svg`를 `div.md-figure`로 감쌉니다). 상자는 `overflow-x: auto`이고, 넓은 표의 상자처럼 `role="region"`, `aria-label`, `tabIndex=0`을 줘 키보드로도 넘길 수 있게 합니다. 이름은 SVG의 `aria-label`에서 콜론 앞(「Recueve 구성도」)을 씁니다. (AI 판단)
- 그림의 폭은 `min-width: 40rem`, `width: 100%`입니다. 데스크톱에서는 본문 칸(47.5rem)을 채우고, 375 화면에서는 40rem으로 그려 상자 안에서 옆으로 넘깁니다(글자 10 ~ 11px). 설명 줄은 넘기지 않고 화면 폭에서 가운데로 둡니다.
- 다크 화면에서도 SVG의 색을 그대로 둡니다. 그림은 흰 카드로 보입니다.

### 챕터 머리 (`src/components/work/chapter.tsx`)

- 버튼은 `links`마다 하나입니다. 이름이 있으면 그 이름(「소개 영상」, 「공개 저장소」), 없으면 지금처럼 「서비스 열기」(ProWith는 「데모 열기」)입니다. 첫 버튼만 채운 모양입니다.
