# /ai에 Jake English 싣기 설계

> 작성: 2026-11-11 (superpowers brainstorming)
> 상태: 자리, 짜임, 그림, 문구를 정했습니다. 4컷은 Gemini로 그린 이야기 4컷과 비교해 둘 다 쓰기로 정했습니다(아래 "그림", 2026-11-11).
> 표시: 「(AI 판단)」은 사용자가 정하지 않고 에이전트가 정한 것입니다. 표시가 없는 결정은 사용자가 비교판이나 질문에서 고른 것입니다.

## 왜 하나

Jake English는 제가 쓰려고 직접 만든 영어 말하기 연습 앱입니다. Android 앱과 집 Mac의 서버로 나뉘고, AI 선생님 라이언과 상황 대화를 주고받으며 연습합니다. 공개한 소개 영상(3분 17초)이 있습니다.

이 앱을 `/ai`에서 눈에 띄게 보여 줍니다. 앱이 무엇을 하는지(상황을 직접 정하고, 듣고 따라 말하기)와, 이 사이트와 같은 방식(AI 에이전트와 하네스)으로 만들었다는 것이 한 곳에서 보여야 합니다.

## 목표

- `/ai` 맨 위에서 Jake English가 "AI 도구 활용 사례"와 같은 무게로 보입니다.
- `/ai/jake-english` 한 페이지에서 소개 영상, 연습하는 방법, 영상의 다섯 장(왜, 어떻게 동작하나, AI와 일한 방식, 일하는 구조, PR 수)을 차례로 봅니다.
- 앱의 핵심을 상황을 직접 정하기와 섀도잉(듣고 따라 말하기)으로 보여 줍니다.

## 하지 않을 것

- 홈의 AI 카드 네 장은 바꾸지 않습니다.
- `/ai`의 "개인 도구" 묶음에는 넣지 않습니다. 같은 내용이 두 번 나오지 않게 하기 위해서입니다.
- 페이지 안에 유튜브 재생기를 넣지 않습니다. 썸네일을 누르면 유튜브로 갑니다("영상 제작" 항목과 같은 방식).
- 아직 만들지 않은 기능(영상을 보며 따라 말하기)은 쓰지 않습니다.
- 이력서와 포트폴리오에는 넣지 않습니다. 사이트 전용 글입니다([ADR-0003](../../adr/0003-content-source-and-sync.md)).

## 실패로 볼 것

- 평가가 앱의 중심처럼 보입니다. 평가는 따라 말한 뒤에 다르게 들린 낱말을 짚어 주는 것으로만 씁니다.
- 공개 글이 AI가 다 했다는 뜻으로 읽힙니다. 사이트 글은 제가 주어인 문장으로 씁니다(CLAUDE.md "글쓰기").
- 확인할 수 없는 숫자를 씁니다. PR 수와 리뷰 수는 `gh`로 센 값만 씁니다.

## 정한 것

### `/ai` 맨 위 띠

- 지금 있는 "AI 도구 활용 사례" 띠와 같은 모양의 Jake English 띠를 둡니다. 머리글은 "APP · Jake English", 제목은 "직접 만들어 쓰는 영어 말하기 연습 앱"입니다. 띠 전체가 `/ai/jake-english` 링크이고, 버튼 이름은 "자세히 보기"입니다.
  - 제목은 직접 만들어 쓴다는 것이 먼저 보이게 정했습니다. "말하기 연습 앱 직접 만들어 쓰기" 어순은 끝의 "쓰기"가 글쓰기로 읽힐 수 있어 쓰지 않았습니다.
  - 시안에서 제목은 1280 폭에서 한 줄, 375 폭에서도 한 줄에 꽉 차게 들어갔습니다. 더 좁은 화면에서는 두 줄이 됩니다.
- 두 띠는 데스크톱(lg, 64rem 이상)에서 나란히 두 칸입니다. 칸마다 글(머리글, 제목, 버튼)이 위에 있고, 작은 그림 네 칸이 글 아래에 있습니다. 모바일은 위아래로 쌓습니다. 순서는 사례 띠가 먼저입니다.
  - 비교한 안: 위아래(사례 띠 먼저), 위아래(Jake English 띠 먼저). 나란히가 두 띠를 같은 무게로 보여 주고, 목차까지 내려가는 거리가 가장 짧습니다.
- Jake English 띠의 작은 그림 네 칸은 페이지의 이야기 4컷을 작게 보여 줍니다. 사례 띠가 4컷을 작게 보여 주는 것과 같습니다. 처음에는 연습하는 방법 4컷의 폰 화면을 정사각형으로 잘라 썼고(AI 판단), 4컷을 C로 정하며 이야기 4컷으로 바꿨습니다.

### `/ai/jake-english` 페이지

`/ai/case`와 같은 틀입니다. 순서는 아래와 같습니다.

1. 돌아가기 링크 "← AI로 일하는 방식"(`/ai`)
2. 머리: 머리글 `AI / APP`, 제목 "직접 만들어 쓰는 영어 말하기 연습 앱", 부제 "Jake English". 사례 페이지(`AI / CASE`, 제목, 부제)와 같은 짜임입니다. 머리글 `AI / APP`은 띠 머리글의 APP에 맞췄습니다(AI 판단).
3. 영상: 소개 영상의 썸네일을 크게 두고, 가운데에 재생 표시를 겹칩니다. 누르면 유튜브(`https://www.youtube.com/watch?v=5FByJLa8R1k`)로 갑니다. 아래에 한 줄(문구 W4)을 둡니다.
4. 이야기 4컷: 소제목 "이야기 4컷", 정사각 2×2(모바일은 한 칸씩), 칸마다 그림 아래 번호와 설명(문구 W11~W14). 앱을 만든 계기부터 쓰는 모습까지를 이야기로 보여 줍니다
5. 연습하는 방법 4컷: 소제목 "연습하는 방법", 2×2(모바일은 한 칸씩), 칸마다 그림 아래 설명(문구 W5~W8). 번호는 붙이지 않고, 칸은 그림 안의 연습 종류 이름(대화 연습하기, 자유 대화 등)으로 구별합니다. 4컷이 정해진 한 순서가 아니라 연습 종류별 모습이기 때문입니다(2026-11-11)
6. 본문 다섯 장: 영상의 순서 그대로입니다. 장마다 머리글(`1 / 5` 등), 소제목, 슬라이드 그림, 문단입니다.
   1. 왜 만들었나: 슬라이드 1/5, 문단 W9-1
   2. 어떻게 동작하나: 슬라이드 2/5, 문단 W9-2
   3. AI와 일한 방식: 슬라이드 3/5(글자를 바꿔 다시 찍은 것, 아래), 문단 W9-3
   4. 일하는 구조: 슬라이드 4/5, 문단 W9-4
   5. 닷새 남짓 동안 머지한 PR: 슬라이드 대신 큰 숫자 "PR 78개"와 작은 글 "2026-11-04 ~ 11-09 · 머지한 PR", 문단 W10. 슬라이드 5/5는 오른쪽 인물 자리가 비어 있어 쓰지 않습니다(AI 판단). 소제목은 영상의 "닷새 동안"이 아니라 W10과 같은 "닷새 남짓 동안"입니다(AI 판단, 아래 "숫자").
7. 끝 링크: "영상 보기"(유튜브, 채움 버튼), "AI로 일하는 방식"(`/ai`, 테두리 버튼)

- 브라우저 제목은 사례 페이지처럼 "<제목> · 소재희", 곧 "직접 만들어 쓰는 영어 말하기 연습 앱 · 소재희"입니다(AI 판단). 검색 설명은 문구 W3입니다.
- 헤더 메뉴는 늘리지 않습니다. 이 페이지에서도 "AI" 메뉴에 지금 보는 곳 표시(밑줄, `aria-current="true"`)를 붙입니다. 지금의 메뉴 코드가 `/ai/` 아래 경로를 이미 이렇게 다룹니다.
- 맨 위로 버튼과 다음 페이지 버튼은 `/ai/case`처럼 두지 않습니다(AI 판단). `/ai/case`와 같은 서브페이지이기 때문입니다.
- "항목마다 따로 페이지를 만들지 않는다"는 F3 원칙의 두 번째 예외입니다(첫째는 `/ai/case`). 영상, 4컷, 다섯 장이 `/ai`의 다른 항목보다 길어 `/ai` 안에 펼치지 않습니다. `docs/02-ia.md`에 이유를 적습니다.

- 이야기 4컷 절의 소제목 "이야기 4컷"과 칸 설명 W11, W12는 후보 가운데 추천안으로 정했고(AI 판단), 사용자가 개발 서버의 화면을 보고 확인했습니다(2026-11-11). W13, W14는 2026-11-11에 사용자가 고쳐 썼습니다. 소희가 늘 첫마디를 알려 주는 것은 아니기 때문입니다.

## 만드는 사람에게 맡기는 것

- 글을 둘 곳과 형식. `content/site/ai/`는 `/ai`의 항목 목록이라 거기에 두면 항목으로 잡힙니다. 그 밖의 사이트 전용 글 파일(예: `content/site/jake-english.md`)에 두기를 권합니다.
- 띠를 사례 띠와 한 컴포넌트로 합칠지. 두 띠는 머리글, 제목, 링크, 작은 그림만 다릅니다.
- 그림 파일의 크기와 형식(JPG 품질, 폭). `next/image`로 넣고, 4컷과 슬라이드는 데스크톱에서 레티나로 봐도 흐리지 않을 폭으로 둡니다.
- 그림을 다시 만드는 방법을 저장소에 스크립트로 둘지. 원본 영상 폴더는 이 저장소 밖에 있어 CI에서 돌릴 수 없습니다. 그림은 커밋하고, 만든 방법은 가이드에 적습니다.
