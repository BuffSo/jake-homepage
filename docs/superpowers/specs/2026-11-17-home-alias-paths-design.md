# 짧은 주소 열 개로도 홈 열기 설계

> 작성: 2026-11-17 (superpowers brainstorming)
> 상태: 방법을 정했습니다(C, 정적 페이지 열 개).
> 표시: 「(AI 판단)」은 사용자가 정하지 않고 에이전트가 정한 것입니다. 표시가 없는 결정은 사용자가 정한 것입니다.

## 왜 하나

홈을 짧은 주소 열 개(`/about`, `/intro`, `/hello`, `/me`, `/profile`, `/welcome`, `/start`, `/info`, `/home`, `/main`)로도 엽니다. 방문 통계에는 주소마다 따로 잡혀서, 링크를 둔 곳마다 다른 주소를 쓰면 어디서 들어왔는지 나눠 볼 수 있습니다.

## 목표

- 열 개 주소 모두 홈과 같은 화면을 200으로 돌려줍니다. 다른 주소로 넘기지 않아 주소창은 그 주소 그대로입니다.
- 방문 통계(`@vercel/analytics`)에 주소마다 따로 잡힙니다.
- 헤더 메뉴의 지금 페이지 표시, 맨 위로 버튼, 다음 페이지 버튼, JSON-LD, 미리보기 그림, 대표 주소가 홈과 같습니다.

## 하지 않을 것

- 화면 모양은 바꾸지 않습니다. 그래서 시안 비교판을 만들지 않습니다.
- 사이트맵(`src/app/sitemap.ts`)에 넣지 않습니다.
- 주소마다 제목, 설명, 대표 주소를 따로 정하지 않습니다.
- `noindex`를 달지 않습니다. 대표 주소가 홈이라 검색엔진은 홈 하나로 모읍니다. 대표 주소와 `noindex`를 함께 달면 신호가 엇갈립니다. (AI 판단)
- 헤더 메뉴와 페이지 순서(`src/lib/nav.ts`)는 바꾸지 않습니다.

## 하면 안 되는 것

- 열 개 말고 모르는 주소(예: `/abcd`)가 404가 아니게 되면 안 됩니다. 지금처럼 빌드 때 만든 404입니다.
- 서버가 그린 경로와 브라우저의 경로가 달라지면 안 됩니다. 경로를 읽는 곳(헤더 메뉴, 방문 통계)이 수화 오류를 낼 수 있습니다.

## 지금 코드에서 확인한 것

- **헤더 메뉴의 지금 페이지 표시**: `src/components/nav-links.tsx`가 `usePathname()`을 읽어 Work, AI, Resume 가운데 경로가 같은 항목에 밑줄과 `aria-current`를 붙입니다. 홈 링크("Jake")에는 표시가 붙지 않아서 홈에서는 어느 항목에도 표시가 없습니다. 열 개 주소는 세 항목과 겹치지 않으므로 따로 고치지 않아도 홈과 같습니다.
- **대표 주소와 미리보기 그림**: 뿌리 레이아웃(`src/app/layout.tsx`)의 메타데이터가 홈의 것입니다(`path: "/"`). 새 페이지가 메타데이터를 정하지 않으면 그대로 이어받아, 대표 주소와 `og:url`이 `https://jakeso.dev`이고 그림도 같습니다.
- **JSON-LD, 맨 위로와 다음 페이지 버튼**: 홈 페이지 컴포넌트(`src/app/page.tsx`) 안에 있습니다(`<ProfileJsonLd />`, `<BackToTop next={nextPage("/")} />`). 같은 컴포넌트를 그리면 같습니다.
- **방문 통계**: `@vercel/analytics` 2.0.1의 `next` 진입점은 `usePathname()`을 `path`로, 경로 규칙을 `route`로 보냅니다. 운영 통계 스크립트(`/_vercel/insights/script.js`)는 `path`가 브라우저 경로와 다르면 보낼 주소의 경로를 `path`로 바꿉니다. 정적 페이지 열 개는 `path`와 `route`가 모두 `/about`처럼 그 주소입니다. 바깥 링크 클릭의 "누른 페이지"도 `location.pathname`이라 그 주소로 잡힙니다.
- **Cache Components**: 이 프로젝트는 `cacheComponents: true`이고 뿌리 레이아웃이 `ensureStatic = "navigation"`입니다. 이 설정에서는 `dynamicParams`를 쓸 수 없습니다(`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/02-route-segment-config/dynamicParams.md`).

## 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. `next.config.ts`의 `rewrites`로 열 개를 `/`에 잇기 | 파일 하나만 바뀝니다 | 미리 만든 홈 HTML을 그대로 보내서, 서버가 그린 경로(`/`)와 브라우저 경로(`/about`)가 다릅니다. 지금은 메뉴가 두 경로에서 똑같이 그려져 오류가 없지만, 경로에 따라 다르게 그리는 것을 더하면 열 개 주소에서만 수화 오류가 납니다(Next `usePathname` 문서의 경고) |
| B. `src/app/[alias]/page.tsx` 하나와 `generateStaticParams`로 열 개, 모르는 값은 `notFound()` | 파일 하나에 목록 하나입니다 | `dynamicParams = false`를 쓸 수 없어서 모르는 한 단계 주소(`/abcd`)가 첫 요청 때 서버에서 그려진 뒤 404가 됩니다. 지금의 빌드 때 만든 404가 아니게 되고, 봇이 훑는 주소마다 서버 실행이 생깁니다 |
| **C. 열 개를 각각 정적 페이지로 두기 (고름)** | 빌드 때 HTML이 열 개 따로 만들어집니다. 서버와 브라우저의 경로가 같고, 모르는 주소는 지금 404 그대로입니다. 추가 비용이 없습니다 | 두 줄짜리 파일이 열 개 생기고, 빌드에 페이지가 열 개 늘어납니다 |

사용자가 C를 골랐습니다. 정한 조건(200, 주소창 그대로, 모르는 주소 404)을 프레임워크의 예외 동작에 기대지 않고 지키기 때문입니다.

## 정한 것

### 파일 (AI 판단)

- 경로 묶음 폴더 `src/app/(home-aliases)/` 아래에 주소마다 폴더를 하나씩 둡니다: `about/page.tsx`, `intro/page.tsx`, ... `main/page.tsx`.
  - 괄호 폴더 이름은 주소에 나오지 않습니다. 열 개가 한 폴더에 모여 `src/app/`의 다른 페이지와 섞이지 않습니다.
  - 묶음 폴더에는 레이아웃을 두지 않습니다. 뿌리 레이아웃을 그대로 씁니다.
- 각 `page.tsx`는 홈 페이지를 그대로 내보냅니다. 메타데이터를 따로 내보내지 않습니다.
  ```tsx
  // 홈을 짧은 주소로도 연다 (docs/02-ia.md 페이지). 화면, 대표 주소, 공유 정보가 홈과 같다.
  export { default } from "../../page";
  ```
- 나중에 열 개 가운데 하나를 다른 페이지 이름으로 쓰려면, 그 주소를 쓰는 링크를 먼저 바꾼 뒤 이 폴더에서 뺍니다. 같은 주소의 페이지를 하나 더 만들면 Next 빌드가 실패하므로, 모르고 겹칠 일은 없습니다.

### 테스트 (AI 판단)

새 E2E 파일 `e2e/home-aliases.spec.ts`에 열 개 목록을 두고 확인합니다. 화면 폭과 관계없는 값이라 데스크톱에서만 돌립니다(`e2e/seo.spec.ts`와 같음).

- `src/app/(home-aliases)/`의 폴더 이름이 목록과 정확히 같습니다. 폴더를 빼거나 더하면 테스트가 알립니다.
- 열 개 주소마다
  - 응답이 200이고, 연 뒤의 경로가 그 주소 그대로입니다.
  - 콘솔 오류와 실패한 요청이 없습니다(`collectErrors`). 수화 오류도 여기서 잡힙니다.
  - 브라우저 제목, `main`의 글(textContent), JSON-LD가 홈과 같습니다.
  - 대표 주소와 `og:url`이 `https://jakeso.dev`이고, `og:image`가 홈과 같습니다.
  - 헤더 메뉴에 `aria-current`가 붙은 링크가 없습니다.
  - 다음 페이지 버튼이 `/work`(포트폴리오)를 가리킵니다.
- `/abcd`는 404입니다.
- 사이트맵이 그대로인 것은 `e2e/seo.spec.ts`의 "사이트맵에 모든 페이지가 대표 주소 그대로 있다"가 이미 정확한 목록으로 확인합니다. 고치지 않습니다.
- 방문 통계는 Vercel 운영 배포에서만 들어가므로 로컬 E2E로 보지 않습니다. 배포 뒤 운영에서 일반 브라우저로 한 주소를 열고 경로가 따로 잡히는지 봅니다(main 세션이 맡음).
