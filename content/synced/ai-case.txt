ProWith는 요구사항이 제각각인 MLM 업체가 쓰는 정산 솔루션입니다. 그래서 업체별로 코드를 고치지 않고 관리자 설정만으로 맞출 수 있게 만들었습니다. 21개 카테고리로 나뉘는 281개의 값을 조정합니다.

새 업체를 추가하는 작업도 처음에는 모두 제가 직접 했습니다. 환경 변수와 docker-compose를 고치고 EC2의 Nginx 설정과 SSL 인증서 발급, RDS의 DB와 계정 생성, ECR과 배포 파이프라인, GitHub Secrets, Vercel 연결까지 하나하나 챙겨야 했습니다. 이 절차를 Claude Code 스킬로 만들었습니다. 지금은 AWS 키를 준비해 두고 도메인과 업체명만 넣으면 HTTPS가 붙은 운영 서버까지 자동으로 올라갑니다. 마지막까지 직접 하던 도메인 DNS 설정도 이제는 AI 브라우저로 로그인부터 등록까지 처리합니다.

보상플랜도 업체마다 다르고 hwp·pptx 같은 문서로 받습니다. 처음에는 제가 문서를 읽고 사양으로 옮겼는데 그 과정에서 착오가 생기곤 했습니다. 그래서 업체에서 받은 문서를 Claude Code가 직접 읽고 정해진 형식의 사양으로 정리하게 했습니다. 단위나 마감 주기처럼 문서만으로는 애매한 항목은 임의로 정하지 말고 저에게 되묻도록 했습니다.

수당이 최대 13종이고 마감이 일·주·15일·월로 따로 돌아서 계산 오류가 하나만 있어도 회원에게 잘못된 금액이 지급됩니다. 정리된 사양은 Claude Code가 업체별 설정과 수당 계산 로직으로 옮기고 검증 스킬을 통과해야 끝난 것으로 봅니다. 스킬이 사양을 읽어 점검 항목을 세우고 시드 데이터에 테스트 매출을 넣은 다음, 네 가지 마감을 차례로 돌려 집계를 맞춰 봅니다. 이미 운영 중인 계산 로직을 고칠 때는 운영 데이터를 복원해 다시 마감하고 기존 결과와 전부 대조해서 한 건이라도 다르면 반영하지 않습니다.

화면이나 기능을 같은 방식으로 만들기 위한 세부 규칙도 가이드 문서로 남깁니다. 목록 표라면 컬럼 폭, 정렬, 페이지네이션, 합계 행까지 정해 두어 화면이 늘어도 같은 모양으로 나옵니다. 검증하다 걸린 문제는 원인과 해결, 재발 방지까지 적어 둡니다. 그렇게 쌓인 문서가 ProWith에 71개, Recueve에 60개이고, ProWith에서 만든 표 규칙은 Recueve 관리자 화면에도 가져와 맞춰 썼습니다.

업체 셋업부터 문서 정리와 설정 반영, 검증까지 스킬로 이어 두어서 새 업체가 들어와도 같은 순서로 같은 기준을 통과해야 실서비스에 올라갑니다. 구현은 AI로 빨라졌습니다. 애매한 규칙을 결정하고 검증 결과를 보고 반영할지 판단하는 일은 제가 합니다.
